# 游戏无障碍案例与需求验证

整理与公开来源核对日期：2026-10-03。本文由听野团队独立整理，介绍可追溯的公开案例与项目待验证的问题。研究案例不构成听野的准确率、玩家体验或适用性结论。

## 可核对的公开案例

| 案例 | 公开材料支持的事实 | 对听野的启示 |
| --- | --- | --- |
| [Hearthstone Access 社区版](https://hearthstoneaccess.com/) | 官网介绍了原作者停止维护后由社区继续开发的过程，并列出当前功能限制；[FAQ](https://hearthstoneaccess.com/faq.html)说明游戏更新可能导致补丁失效 | 辅助工具需要维护和问题反馈机制，不能只交付一次演示 |
| [Minecraft Access](https://github.com/minecraft-access/minecraft-access) | 项目 README 描述了读屏朗读界面、声音提供三维方位线索的方案，并说明先在社区测试、收集反馈后再发布 | 可借鉴多种信息表达方式及体验反馈流程，实际效果仍需按用户和任务验证 |
| [Accessibility Mods](https://accessibilitymods.com/) | 官网展示读屏、导航音频、音频描述和色彩滤镜等辅助方式；Mod Manager 处理下载、依赖、设置与更新，区分公开版本和会员版本 | 安装、配置和更新也是可用性的一部分，贡献与分发方式可以分别设计 |
| [Game Accessibility Guidelines](https://gameaccessibilityguidelines.com/) | 网站提供由游戏工作室、专家与学术参与者共同整理的无障碍设计参考 | 将无障碍要求转化为可操作的设计与体验检查项 |

这些项目采用的游戏类型、运行平台和技术形态各不相同。案例中的读屏或 mod 功能不能直接证明手机上实时小地图提示有效；听野仍需验证自己的采集、事件筛选、声音与触觉输出链路。

## 社区维护能说明什么

Hearthstone Access 的[原作者停更说明](https://hearthstoneaccess.github.io/sunsetting-hearthstone-access.html)描述了持续适配游戏更新所需的时间和精力。社区官网及[更新日志](https://hearthstoneaccess.com/changelog.html)展示了接力维护和版本适配，也记录了部分功能暂不可用的情况。它支持“社区可以参与持续维护”的判断，同时说明兼容性与维护投入需要长期处理。

Minecraft Access 的 README 列出测试、文档、翻译、教学与开发等贡献方式，体现了代码以外的协作需求。对听野而言，可复现的问题反馈、清晰的安装说明和容易接手的文档同样是项目持续运行的工作。

Hearthstone Access 的 FAQ 确认工具免费，Accessibility Mods 官网区分公开与会员版本。免费使用、收入、资助和维护成本属于不同事实；公开页面不足以支持“没有任何资金来源”或某种运营模式必然更稳定的结论。

## 听野仍需直接验证的需求

公开案例支持继续研究游戏无障碍表达，不能代替目标玩家访谈和本项目的实测。下一步围绕以下问题记录反馈：

| 验证问题 | 建议保留的证据 |
| --- | --- |
| 玩家是否会遗漏当前画面边缘或小地图中的信息？ | 玩家对具体任务的描述、对局时刻与经授权的问题记录 |
| 方位短音、语音与震动是否容易理解？ | 试听辨认、误解、需要重听或调整设置的反馈 |
| 提示是否有帮助，是否干扰操作或队伍语音？ | 相近任务中开启与关闭辅助的体验记录、误报与漏报问题 |
| 手机发热与提醒时效是否可接受？ | 版本、设备、测试条件、会话时长、诊断记录与实际听到的声音 |
| 其他类型低视力玩家是否适用？ | 分开记录不同使用情况，不从单一案例推导所有玩家的效果 |

试用方式与反馈表见[玩家试用套件](../../validation/PLAYER_TRIAL_KIT.md)，已有证据和未完成项见[当前验证状态](../../validation/STATUS.md)。记录时使用匿名编号，公开材料只呈现必要的汇总和经授权的反馈。
