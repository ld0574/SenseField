日期：2026-10-03；工程联调更新：2026-10-04。本文记录已能定位的实现、公开边界和仍待取得的证据，不替评估者重新判档。

2026-10-01 评估材料给出的 52.96% 是当时展示材料的历史判定，不是当前代码审计、赛事最终分数或下一版本目标。本文不推算分数、不计算“可回收分”，也不把实现或自动化测试直接写成需求已满足。35 项需求逐项的历史与现状对照见[评审补强 Goal](../../validation/SCORE_RECOVERY_GOAL_2026-10-03.md)。

0.4.0 中的语音/画面助手是额外的实验能力。它不替代端侧小地图预警，也不会自动改变历史需求判档。助手范围、接口、外部录音口径与验收清单见[0.4.0 Goal](../../validation/GOAL_0.4.0_2026-10-03.md)。

## 证据原则

每项需求至少分开记录以下内容：

1. 需求原文及适用范围；
2. 当前代码路径和实际测试名；
3. 同一 session、turn、frame 或 cue ID 下的运行诊断；
4. 适用时的外部录像/录音时间码和人工标注；
5. 未验证的设备、数据、无障碍体验和失败情形。

缺少任一适用证据时标为“未测”或“未知”。开发集结果不能替代独立留出；TTS/AudioTrack 回调不能替代外部录音中的实际声音；用户主观反馈不能推导检测准确率、发热或延迟。

## 0.4.0 助手的数据流与隐私说明

### 选择式数据流

- 助手语音与画面均默认关闭，并在设置中分别选择和确认；低频主动观察还需要单独开启。核心本地识别不依赖这几个开关。
- 开启语音后，用户授权的前台截屏服务可在应用切至后台后继续运行，系统持续显示前台服务通知。活动会话期间 `AudioRecord` 使用 `VOICE_RECOGNITION` 获取 16 kHz 单声道 PCM；端侧 WebRTC VAD 2.0.10（mode 3）只向用户配置的 HTTPS 网关发送检测到的语音片段，并附带最多约 300 ms 的预滚动音频；VAD 门外的其余采样不上传。ASR 在网关 CPU 上由 Python FunASR 运行，应用不把识别回调时间当成物理声音时间。
- 开启画面理解后，显式问题会把对应当前帧 JPEG 与问题发到用户配置的 HTTPS 网关；低频主动观察只有在其独立开关打开后才可请求。网关再把帧和问题转给 GLM-4.6V-Flash。该路径是远端视觉服务，不是本地 OCR。模型被限制为读取可见 HUD、菜单、比分等界面信息，并拒绝战术建议；这些限制不能证明模型零误答。
- 语音音频只发送到配置的 ASR 网关；当前 GLM 视觉后端不会收到麦克风音频。视觉请求会到网关及其配置的模型服务。核心本地预警在助手断网、暂停、权限撤销或热档时仍单独运行。
- 助手回答由设备上可用的中文 TTS 合成。代码只允许助手使用被系统报告为无需网络的中文语音；没有这类语音时，回答可能无法播放，短音/触觉预警不依赖这项能力。

### 已有的数据控制与未核实项

- 客户端仅接受 HTTPS 网关地址，明文传输被禁用。设备凭据用于网关鉴权；GLM API 密钥只在网关配置，不应进入 Android 源码、APK、Git 或诊断日志。
- 网关应用代码不创建对话数据库或音频/图片归档；ASR 队列、解码图像和模型请求在进程内处理。部署反向代理、主机日志、崩溃转储、模型服务商的数据用途/保留期限尚未独立审计，不能承诺端到端零留存。
- 客户端审计记录事件类型、ID、耗时和结果码，不记录识别文本或 GLM API 密钥。界面最多保留 12 条会话消息于内存；助手语音合成会写入应用 cache 临时 WAV，并在正常完成或失败路径尝试删除。异常进程结束后的缓存清理仍需检查，因此不要把该实现表述为“从不落盘”。
- 诊断包中的本地截图是另一项已有功能，由诊断设置控制；不得把助手的网络开关与诊断截图开关合并说明。用户关闭助手图片上传，不会自动删除先前导出的诊断包。
- 智谱公开价目页与模型说明在 2026-10-03 标示 GLM-4.6V-Flash API 输入/输出免费（[价格页](https://docs.bigmodel.cn/cn/guide/start/pricing)、[模型说明](https://docs.bigmodel.cn/cn/guide/models/free/glm-4.6v-flash)）；账号额度、并发/速率限制和网关服务器成本仍适用，不能据此称整体服务没有成本。上游 GLM 服务条款、数据使用和留存期限需要在接触参与者前按实际账户/服务条款留档复核。

相关实现：`AssistantSettingsActivity`、`AssistantSettings`、`AssistantController`、`AssistantVoiceInput`、`AssistantGatewayClient`、`python/mapassist/assistant_gateway/config.py`、`app.py`、`glm.py`。权限与 TLS 配置见 `android/app/src/main/AndroidManifest.xml` 和 `android/app/src/main/res/xml/network_security_config.xml`。

| 主题 | 当前事实 | 不应写成 |

| HRTF | 可选声音路径使用合成立体声、声像、短时差和简化频谱整形；不开启时保留现有短音 | “已实现 HRTF”“提供可靠上下定位”或“支持三个独立声源” |
| 震动 | 默认振动器；方向是节奏模式。距离选项以振幅控制或时长编码实验，不表示马达物理方位 | “左右马达已支持”或“玩家一定能感觉到” |
| TTS 与 ASR | 助手回答在本机可用的离线中文 TTS 合成；语音识别在自托管网关运行 | “全程离线语音”“任一 Android 设备都有中文离线 TTS” |
| OCR | 仓库没有已接入的本地 OCR 引擎；当前画面文字问答会把所选帧送往配置的视觉后端 | “本地 OCR 已实现”“屏幕文本不会离开设备” |
| 麦克风与回声 | `VOICE_RECOGNITION` + `AudioRecordingCallback` 监测系统静音；WebRTC VAD 2.0.10 mode 3 在本地分类。Android 10/API 29+ 用本应用 `USAGE_GAME` 静音探测轨道的 `getRoutedDevice()` 和路由回调确认有线/USB 耳机；BLE 路由识别从 API 31 起可用。用户须先确认游戏声已在耳机中；该探测不能证明游戏自行指定设备的轨道也走耳机。未知/无耳机/探测失败时暂停上传；`isClientSilenced()` 或任意其他录音会话出现也暂停上传，恢复时清空旧轮次。静音短缓冲无限循环、不申请 audio focus、不设首选设备；可能增加 native 音频负载，仍待热/负载对照实测 | “已采集游戏播放音频”“活动游戏/媒体声路已被本应用确认”“使用系统硬件 AEC”“保证不与游戏语音冲突” |
| 投影停止 | `MediaProjection.Callback.onStop()` 会将采集标为撤销并停止当前服务；恢复需要用户重新授权 | “onStop 后自动恢复”“已接入 checkpoint 自动续传” |
| ASR 版本 | Python 依赖锁为 `funasr==1.4.16`；模型清单记录 `funasr/paraformer-zh-streaming` tag `apache-2.0-20260804`、revision `fd2af606b37d7fb8b3b8a218c5be5b07b53ef6ba` 与权重 SHA-256；这是网关 Python ASR，不是 Android 原生 C++ runtime | 将模型 tag、FunASR Python 包版本和推理运行时写成同一个版本号 |

此前草案中的本地 ncnn/ONNX OCR、MediaProjection playback capture、DashScope/Qwen 价格与留存期限等未由当前仓库实现或当前服务配置证明，已从本方案中移除。今后引用供应商价格、数据保留或 API 规则时，应带来源与核验日期，并按实际账户条款确认。

## 0.4.0 验收与测量

合并树工程回归、真实 GLM 合成图与 Android HTTPS/WSS 的真实 CPU ASR/视觉联调已通过，见[安卓传输记录](../development/assistant-android-transport-test.md)。本目标尚无真人参与者、外部录音、受控温升或玩家验收通过结果；这些门禁保持“待测”。

1. **设置与撤销**：语音、画面、主动观察三个开关分别验证默认关闭/开启/关闭；关闭后以网关请求日志确认没有相应请求。确认必须在用户授权的截屏会话内运行，并检查会话结束/`onStop` 后录音和请求均停止。
2. **服务安全**：使用 HTTPS；网关仅接受配置的设备 Bearer 凭据；确认日志不含凭据、完整文本、音频或图像。扫描提交候选，运行 `python scripts/check_public_repo.py`；实际密钥只通过部署环境配置。
3. **模型与数据条款**：核对模型清单中的仓库、revision、文件哈希和许可证；在目标服务账户下记录图像数据用途/保留条款。未完成前不把服务商路径描述为适合敏感数据。
4. **语音物理时延**：使用外部录像标注用户说话起点、说话结束、真实静音、正在播报的助手音频和其真实停止时刻。脚本 `python -m mapassist.measure_assistant_latency` 只接受 `external_recording` 标注；按 session/turn/audio ID 报配对样本数、缺失数、P50/P95。外部可见的 `final_recognition_ms` 用于统计用户说完至 ASR 终态的 P95（目标 ≤1 s）；语音触发 HUD 问答以说话结束至首段有用回答的物理声音 P95 ≤4 s。缺值保留 unknown，不用 App 回调填入。
5. **分开服务指标**：网关 `asr_ms` 当前从 utterance start 计至 final event 发出，GLM `elapsed_ms` 是视觉服务时间；都不是端到端“听见有用回答”的延迟。分别报告，不互相替代。
6. **设备与体验**：记录手机型号、Android 版本、音频设备/路由、网络、开始温度、每 5 分钟温度/热档/电量、游戏帧率、错误/无关提示、漏答与中断。热/负载对照至少做 3 组 15 分钟运行；候选相对对照的电池温升增量门槛 ≤1°C、native processing P95 回归 ≤10%。实施前预先定义起始温度匹配范围（建议配对相差 ≤1°C）。实际能否听清、是否有帮助、是否妨碍游戏由参与者直接评价。
7. **近区与既有小地图门槛分开**：500 ms 是 near-zone 观测年龄预算；外部实声 P95 ≤500 ms 是陪同试点目标；两者都不等于严格最终门槛。既有门槛真实声音 P95 ≤250 ms、平均处理 ≥8 FPS、最大处理帧间隔 ≤2 s、冻结配置/parity/独立留出等保持不变；助手测量不为小地图指标背书，也不改变 `verified` 或 `release_ready`。

CSV 表头和计算规则见[0.4.0 Goal](../../validation/GOAL_0.4.0_2026-10-03.md)。`nearest rank` 的 P50/P95 只是对有效配对时差的统计；样本不足时报告数量与分布，不宣称通过。
