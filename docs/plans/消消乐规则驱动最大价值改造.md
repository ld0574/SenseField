# 消消乐规则驱动的最大价值 Goal

2026-10-11。依据用户指定的[开心消消乐元素规则参考](../research/开心消消乐元素规则参考.md)，接续[识别飞轮](消消乐识别飞轮改造.md)和[目标价值排序](消消乐目标价值排序.md)。

## 新目标与完成范围

把“最大价值”升级为根据真实元素规则、当前任务、剩余步数和棋盘状态选择最有价值的合法动作。识别飞轮提供外观证据；规则引擎负责动作是否合法、会触发什么状态变化、哪些变化真正推进任务；排序基于这些结果，并保持高亮、语音、回放和收益观察同源。

本轮需要实现可追溯的规则目录、独立状态与动作模型、确定性效果／已知拓扑推演、有界后继搜索、任务价值排序及工程验证。旧阶段 2“只靠修识别＋空间距离、不做前向推演”的范围在此扩展。先处理规则错误和漏掉的动作，再比较价值，不能仅调整现有排序权重。

“最大价值”指当前已确认状态、已支持规则和声明的搜索范围内的最佳候选。随机补子、无法判定的机制参数和未观测状态保留未知，不能据此声称全局最优或保证通关。用户已说明暂无独立语料，继续完成实现与工程验证；独立准确率／排序、签名 Release、实体手机验收分别待条件，不再用它们阻塞可完成的工程工作。

## 规则证据与全量覆盖

参考文档是本轮的规则输入。目录至少记录 `rule_id`、元素／变体、前置状态、合法动作、触发条件、状态转移、目标事件、精确参数、来源章节、证据等级和支持状态。把“文档已核实”“参数齐全”“工程实现”“当前视觉状态确认”“实局验证”分别记录，不把一种状态当成其余状态。

`[待核实]` 与“部分核实”的条目不能自动升级。即使条目未标待核实，描述只有“大面积”“约 5×5”“产生更多特效”等也不足以生成精确命中集合、次数或收益。同名冲突须以变体和来源取证；缺参数先登记未知和需要的证据，同时继续实现有明确参数的规则。

## 实施顺序

### A．规则目录与冲突消解

- [x] 读取参考文档，审计现有状态／动作／价值代码，登记上述缺口。
- [x] 落地机器可读规则目录及全量覆盖表，逐项区分文档状态、参数完整度、代码支持和视觉支持。
- [x] 优先核对冰的两个变体、小鸡目标事件、蜂蜜／蜜罐、雪花／冰花及特效触发条件；为冲突保存依据，未消解的具体变体不能继续发确定收益声明。
- [x] 接通现有三轴复核与 gallery：样例绑定规则 ID／版本和状态，不由身份名称或整簇相似度直接授予新规则。旧已确认样例按原来源保持兼容，不能批量改标签。

### B．状态、合法动作和一步效果

- [x] 扩展棋盘状态：底层、前景、覆盖、对象归属、层数／损伤、特效方向、能量／开闭／暂时消失状态，各自允许未知值。
- [x] 把交换、配对、特效触发、受击条件独立建模；枚举已支持的普通交换和特效交换／激活动作，验证动作前提。冻结动物不作配对，锁链动物不作交换端点但可在规则允许时配对。
- [x] 实现纯逻辑的一步事件结算：消除、受击、去层、转化、孵化触发、解救、送达、充能及机关传播；按对象和事件去重，按实际轮次结算，不统一按“邻接一个格子清除一个目标”处理。
- [x] 区分特效生成与现成特效触发，先接参数明确的直线与魔力鸟规则，再接精确参数已齐的爆炸／组合／机关；传播必须有终止及预算，未知区域不能填成普通动物。
- [x] 只在出口、连接关系和重力规则已确认时推演现有棋子的确定落位、送达和连锁。补入的新动物仍未知，不生成有利的随机颜色。

### C．按任务语义比较价值

- [x] 目标增加事件模式：消除、孵化收集、解救、送达、充能／机关触发；图标身份与模式证据分开，模式未知时不发确定进度。
- [x] 比较当前动作能确定完成的目标、剩余任务贡献、瓶颈覆盖／通道进度、有用特效／机关收益和扩散风险，结合剩余步数。目标收益按剩余量封顶，已完成目标不重复加分。
- [x] 首先计算一步确定结果，再在已知后继状态内做有界搜索，初始最多两步；节点数／时间预算须在测量前固定，超限回到已完成的一步结果。未知结果返回范围或未知，不计成确定完成；最后一步不靠下一回合的特效翻盘。
- [x] 最大价值模式、截图工具、实时高亮／语音、回放 producer、收益观察共用同一候选与规则结算。输出动作前提、规则版本、确定收益、准备价值、未知原因和搜索范围；短语音只说有证据的动作及理由。

### D．工程门禁与复现

- [x] 用规则说明独立指定动作及后继状态，覆盖合法／非法、层数／状态转移、特效方向与生成、特殊交换不形成三连、受击去重和目标事件；不能由被测评分函数生成期望值。
- [x] 关键反例必须通过：冰封动物不能补三连；锁链动物不能移动但允许规则内配对；孵化目标不因三消黄色加计数；未知多层蜂蜜不报已清除；毛球普通三消无效；临时毛球移除不报永久完成；宝箱不按障碍击毁；金豆荚未到出口不算收集；未满能量组合／待核实组合不能发已确认动作；方向相反的直线不能命中同一角落；多格救援对象不按格重复计数。
- [x] 排序对照覆盖“小三消直接完成任务胜过无关大消除”“孵化／解救／送达动作与普通动物任务不同”“确定特效收益胜过单纯空间接近”“最后一步只比较当前可兑现收益”；未知重要规则时保留相关弃权原因。
- [x] 扩展排序评测与真实 producer 的动作格式，支持普通交换及特效动作；继续固定源码、规则目录、gallery、清单和帧 SHA，记录非法动作、错误规则收益以及 top-1／top-3。无独立人工真值时不产生独立任务相关率分数。
- [x] 跑与改动相符的 Python／JVM／Debug 工程门禁和固定开发回放；同实现、同输入成对测成本，预声明 P95 ≤+10%，保留首次失败。不得用少读帧、删反例或调宽规则／视觉阈值换通过。限定工程结果通过，完整 Debug strict 准确率仍保留原两条分歧导致的失败。
- [x] 更新规则覆盖、复现命令和缺证据清单。所有参考条目必须有状态；规则工程实现和端到端视觉接入分别验收，不能用合成盘证明新元素在真实盘已识别。
