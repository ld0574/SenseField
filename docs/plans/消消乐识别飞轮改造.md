## 病根（基于当前代码）

- 识别压在 `assets/match3-fixed-ui-v1.json` 一本手工目录上。当前 **324,062 字节 / 上限 327,680**（`Match3VisualCatalog.get` 的硬门），仅剩约 3.5KB，物理上快写不进新元素。
- 识别链路 `Match3Sampler.samplePosition`：`obstacle()` 模板 MAD(.12/.025) → `animal()` face/body → HSV 兜底。每个新家族（金罐／冰花／饼干／大物体…）都要「录屏→读帧→手工塞像素+规则→写回归→重编重装」，正比于关卡/元素数。
- 新元素「识别不到」是设计使然：`Match3UnknownElements` 只把陌生外观聚成会话诊断（每会话 ≤24 家族、各 2 张图），原型「永不进入识别/规则目录」。不手工扩目录，它永远不可操作。
- 排序是识别的下游：`Match3MoveRanker` 的级联只有在 `goals.hudVerified` 且格子被认出时才有效；HUD 读不出（如 `step_badge_unverified`，真机第 54 关 23 条推荐全退化）或格子 UNKNOWN 时，退回「三连长度/消除数」等与任务无关的键。故「准确率不行→排序不行」是一条链，根在识别与 HUD 读数。

## 已决定的方向

- **路线**：自动标注飞轮 + 度量学习 gallery。加新元素 = 往 gallery 加几张带标签样例即生效，不改代码、不撞 327KB 墙、不重训。
- **不做**：本轮不投入消消乐前向模拟器（级联/重力）；排序先靠修识别 + 留出对局评测。
- **红线变更**：选 gallery 路线等于把消消乐线一直冻结的「本地训练/端上模型」正式解禁，范围限定为：标注/训练在本机对已回采的私有录像离线做，推理在端上，**不外传游戏画面**，与 `python/mapassist/` 小地图特性现状一致。
- **复用**：仓库已有给小地图做的 YOLOX-nano 检测 + COCO 数据集 + 预标注复核队列（`training/prelabel_review_queue.py`）+ holdout 盲评（`python/mapassist/`）。消消乐识别本质是网格贴图分类，可复用这套管线。

## 识别器不是推翻重写

现有识别数学（`Match3VisualCatalog.recognize` 的 MAD+接受/余量、`Match3AnimalAppearance` 的 face/body）保留。变的是**样例从哪来、怎么加**：由标注管线批量产出，而非手工编辑 JSON。固定目录推广成可扩展 gallery。三个标签轴与现有代码一致，分别取证：

- **身份** identity：是哪种家族（全自动聚类 + 一次人工标注）
- **可交换** swap permission：是不是普通可换动物（一次标注）
- **机制规则** rule：被消时的效果（每家族最少人工确认一次；图里推不出机制）

## 自动标注飞轮（把人工从 O(关卡) 变成 O(家族)）

你不再逐关录屏给我调。你录一批覆盖元素种类的对局（不是 1000 关），管线自动把所有帧里每种不同贴图/目标图标聚类去重，你给每个「唯一家族」标一次三轴。元素家族远少于关卡数（1000 关大概也就几十种），人工塌缩。

1. **harvest 采集**：扩 `Match3UnknownElements`／采样链路，按去重导出所有不同的逐格 envelope + 目标栏图标，而非逐帧堆图。沿用 `pull_android_diagnostics.py` 的 ADB 自动回采与现有图片预算。
2. **dedup 去重**：离线工具（新建，置于 `python/` 挨着 mapassist）汇总全部会话样例，用同一描述子跨语料聚类成全局家族。
3. **label once 标一次**：家族进入复核队列（`training/prelabel_review_queue.py`），人工给每家族标三轴一次。唯一人工步，O(家族)。
4. **compile gallery 编译**：导出 gallery（样例+标签+嵌入）为 app 资产，取代/兜底 `match3-fixed-ui-v1.json`。
5. **holdout 门禁**：留出一片带标签样本，量 漏认/认错/误放，取代拿工程回归冒充 `verified`。

## 分阶段

- **阶段 0（本批）**：先把准确率量出来。建 holdout 准确率口径（标签 schema + 评分器 + 真实引擎 producer），把现有目录跑出覆盖/漏认/认错/误放基线。只加新文件，不动在飞分支的 match3 代码。详见下节。
- **阶段 1**：识别飞轮 + gallery。harvest→dedup→复核队列标三轴→编译 gallery→holdout 门禁。产出：加新元素不改代码、不逐关录屏、准确率有数。
- **阶段 2**：排序（无模拟器）。先靠阶段 1 补稳识别与 HUD（排序大半问题是识别拖累，会自然消失）；再建「留出对局评测」：冻结真实回放盘 + 人标「哪步推进目标」，量 `Match3MoveRanker` 的 top-1/top-3 任务相关率，取代工程回归冒充。保守的 `Match3MoveValue` 下界模型保留。

## 阶段 0 详细设计

**口径（指标定义）**，均按格子、按家族并给总体：

- **coverage 覆盖**（无需真值）：识别器给出可定身份（非 UNKNOWN/SURFACE、动物且交换权限非 UNKNOWN）的比例。
- **漏认 miss**：真值已知家族，识别器弃权。
- **认错 misclassify**：识别器给出已知家族但 ≠ 真值（身份认错，最伤）。
- **误放 false-swap**：真值不可交换/未知，识别器判为可交换（造假走法，最危险）。
- **漏换 swap-miss**：真值可交换，识别器判不可交换（损失推荐，安全）。

**数据流（三份制品，按样本 id 关联）**：

- `labels.json`：人工真值（O(家族)）：`{id, family, kind, color, swappable, rule, source}`。
- `manifest.json` + 帧：holdout 输入（私有或合成）。
- `predictions.json`：真实引擎产出：`{id, kind, color, swap_permission, ice}`。

**真实引擎 producer**：`Match3HoldoutAccuracyInstrumentedTest`（androidTest）读清单、跑真实 `Match3Sampler.samplePosition`、输出 `predictions.json`。走真实运行链路（obstacle/animal/ice/大物体/HSV 兜底），不另写识别逻辑；无清单时 `Assume` 跳过，不影响现有门禁。

**评分器**：`scripts/evaluate_match3_accuracy.py` 只做关联+评分+报表+门禁（不复刻识别逻辑）。本机 Python 可跑；合成样例 + unittest 自测分支（命中/漏认/认错/误放）。

**本阶段不阻断**：仅记录现状基线（纪律：不伪造通过）。`--max-false-swap`／`--min-coverage` 门槛留给阶段 1 启用。

- **带标签准确率（人工网页标注确认，10 盘 743 格）**：correct 622、**misclassify 0、false_swap 0**、miss 104、swap_miss 37。引擎一旦下结论身份零错、也从不给障碍发交换权；病在**过度弃权**。miss 分解：空/背景→SURFACE 46（两者都不可下，游戏影响小）、雪花变体漏认 15、普通动物过保守弃权 37(=swap_miss)、银币 6。真正新/未知元素仅 17 格（unknown 15、special 2），引擎如实弃权未计对错。

## 阶段 1 起步（本批已落地：harvest + 跨会话去重）

app 已在录制里导出陌生元素代表图（`diagnostics/current/elements/uN-M.png`）与 `Match3ElementObserved/Sample` 事件，但家族 id 每会话重置。`scripts/match3_cluster_unknown_elements.py`（需 `.venv/bin/python`，Pillow+numpy）把全部会话的代表图按 16×16 描述子跨会话聚类成全局家族，产出复核清单 `review-manifest.json` 和**空白** `labels.todo.json`（只组织「要标什么」，绝不预填真值）。

- 真实结果：历史录制 3 个会话 74 张代表图 → **36 个全局家族**（阈值 0.12）。即覆盖这些会话里所有陌生元素，人工只需标 ~36 次，而非逐关调试。示例 `g3` 把 A 会话的 `u17` 与 B 会话的 `u1/u3/u8/u13` 合并，正是端上按会话聚类做不到的跨会话去重。
- 诚实边界：这是端上 `Match3AnimalAppearance.Body` 描述子的离线近似，缺 ±2 对齐与象限检查，36 是**上限**（加对齐会再合并）；权威去重仍应走端上描述子。标注是人工 label-once 步，不训练、不预填。

## 阶段 1 gallery 首刀（已验证，留出盘 train/test）

无上限 sidecar `assets/match3-gallery-v1.json`，由 `Match3VisualCatalog.mergeGallery` 合并进识别（不碰 327KB 墙）。`scripts/match3_build_gallery.py` 只从**训练盘**抽样例：普通动物 body + 银币模板。诚实 5训练/5测试，在**没喂进去的测试盘**上量：

- 动物过度弃权 swap_miss 19→**4**，coverage 0.814→**0.856**；
- 留出盘 `feedback-live-043645` 银币识别 12→**17**（全数救回，银币样例来自 `task-feedback-0`）；
- **false_swap 全程 0**（安全没破）。
- 指标里仅有的 2 个「认错」经核图都是**聚类把棕熊误并进狐狸家族 `c30`**导致的标注噪声，引擎其实读对了——是标注问题，不是识别回归。

证明方案核心：往无上限样例库加样例即可安全压低过度弃权，不改识别逻辑、不撞容量墙、扩展随样例线性增长。该 gallery 为实验级（仅由这些盘种出、未过完整门禁），正式发布需用正规语料重种并过门禁。

## 机制原型表（固化 2026-10-10）

识别靠数据（gallery），机制靠这张**有限**的原型表（写死一次）。新元素 = 标长相 + 选原型（标注页 `match3_make_label_page.py` 已内置两个下拉，②机制按①长相自动预填）。表外没见过的原型 → 引擎**弃权**（`false_swap` 保持 0），不会乱推荐。

| 原型 | 含义 | 今天确认的元素 | 引擎建模 | 状态 |
|---|---|---|---|---|
| ordinary 普通可交换 | 可交换动物 | 棕熊/狐狸/河马/小鸡/青蛙/紫猫 | `ANIMAL` + body gallery | 已接、已验证 |
| single 单级·相邻消 | 相邻消一次即没 | 银币、蜜罐、雪块 | `COIN`/`HONEY`/`SNOW`，相邻 `layers==1` 计数 | 已接 |
| multistage 多级 | 消完变成另一种再没 | 冰花→雪块→没 | `ICEFLOWER`，相邻清一层计 1 | 已接 |
| cover 覆盖层 | 动物压上面，消动物→底下清 | 透明冰块 | `iceLayers` + `ICE` 目标 | 已接（识别待补样例）|
| spawner 生成器 | 消不掉，旁边消触发生成 | 鸡窝/蛋→生小鸡 | `EGG`，不计直接消除、`EGG→CHICK` 相关 | 已接 |
| large 大物体 | 2×2 占四格 | 饼干 | `large_objects` 2×2 | 已接、已验证（留出 48→60/68）|
| special 特殊 | 彩虹/爆炸等组合 | 彩虹猫头鹰 | 未建模收益 → 弃权 | 保守弃权 |
| unknown 未确认 | 没见过 | — | 弃权 | 保守弃权 |

规律：**机制**落在表里→已写死；表外的全新原型→写一次即可（很少）。**识别**永远走 gallery 加样例、不写代码。两者都没覆盖→安全弃权。这就是"后面还有一堆消除逻辑怎么办"的答案：不逐个手写，收敛到这张表。
