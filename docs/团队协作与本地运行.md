## 最快开始：参与小地图标注

标注服务只需由一台电脑启动。其他同伴在同一可信 Wi-Fi 下直接用浏览器打开局域网地址，不需要克隆仓库，也不要各自复制数据库后同时标注。

主机执行：

```sh
source .venv/bin/activate
PYTHONPATH=python python3 -m mapassist.annotation_server \
  --dataset video1-hd=data/private/minimap-review-video1-hd-v1 \
  --dataset video2-hd=data/private/minimap-review-video2-hd-v1 \
  --dataset video3-hd=data/private/minimap-video3hd-new-match-20260928-a/blind-review-v1 \
  --dataset video4-hd=data/private/minimap-review-video4-hd-v1 \
  --dataset video5-hd=data/private/minimap-review-video5-hd-v1 \
  --dataset video7-edge=data/private/minimap-review-video7-edge-recheck-v1 \
  --dataset video8-hd=data/private/minimap-video8-holdout-v1/blind-review-v3-safe-roi \
  --dataset video10-11-hd=data/private/minimap-video10-11-hd-development-v1/queue \
  --dataset video13-hd=data/private/minimap-video13-holdout-v1/queue \
  --host 0.0.0.0 --port 8765
```

终端会打印局域网地址。把地址发给同一可信网络中的同伴，每人使用不同的标注员名字。当前 HD 队列都在顶部菜单中切换，并共用 `8765` 端口；每个队列的数据库与清单分别保存。旧低清队列不在默认启动项中。网站没有账号和访问控制，只能在可信局域网内使用，不能映射到公网。

单人在主机上标注时使用同一队列和端口：

```sh
PYTHONPATH=python python3 -m mapassist.annotation_server \
  --dataset video1-hd=data/private/minimap-review-video1-hd-v1 \
  --dataset video2-hd=data/private/minimap-review-video2-hd-v1 \
  --dataset video3-hd=data/private/minimap-video3hd-new-match-20260928-a/blind-review-v1 \
  --dataset video4-hd=data/private/minimap-review-video4-hd-v1 \
  --dataset video5-hd=data/private/minimap-review-video5-hd-v1 \
  --dataset video7-edge=data/private/minimap-review-video7-edge-recheck-v1 \
  --dataset video8-hd=data/private/minimap-video8-holdout-v1/blind-review-v3-safe-roi \
  --dataset video10-11-hd=data/private/minimap-video10-11-hd-development-v1/queue \
  --dataset video13-hd=data/private/minimap-video13-holdout-v1/queue \

```

停止服务按 `Ctrl+C`。每个队列的进度保存在其目录下的 `annotations.sqlite3`，重启同一命令会继续原进度。数据库使用 WAL 和 15 分钟任务租约；不要在服务运行时手工编辑 `review-manifest.json` 或复制数据库。

### 标注规则

先看完整画面，确认当前是对局中的 HUD。准备、选人、加载、结算等画面使用 `excluded`，不要标成没有敌人的 `negative`。

| 状态 | 什么时候使用 |
| --- | --- |
| `accepted` | 自动建议框完整且位置正确 |
| `corrected` | 删除错框、移动框或补全漏掉的小地图敌人后保存 |
| `negative` | 对局中画面，确认小地图上没有该类敌人目标 |
| `excluded` | 准备、选人、加载、结算等非对局界面 |
| `skip` | 画面模糊、遮挡严重或无法确定 |

### 旧低清录像质量记录（历史）

此前低清录像为 720×324 或 960×432，视频码率约 0.53–0.99 Mbps；裁出的小地图通常仅 104×108，最小敌人头像宽度约 6 像素。该说明记录旧数据限制，不是当前采集或模型流程。新录像请优先使用手机原生横屏分辨率和录屏的“高画质／高码率”设置；1080p、30 FPS 可先以 8–12 Mbps 为目标。录完先运行：

```sh
ffprobe -v error -select_streams v:0 \
  -show_entries stream=width,height,avg_frame_rate,bit_rate \
  -of default=nw=1 video/新录像.mp4
```

这些低清来源不再进入本轮数据。未来如新增素材，必须先登记 HD 来源与数据分工，再依获准流程处理。

`video7.mp4` 已按这一要求录成 2712×1220、30 FPS、约 8 Mbps，证明高分辨率能显著改善人工辨认，但冻结盲测仍只有 65.57% precision / 63.49% recall。它现已降级为开发数据，并建立上面的扩展队列。video7 属于获准的 HD train/dev 来源；新的素材必须先按本轮数据划分登记。

## 首次安装开发环境

### 必需软件

- Python 3.10 或更高版本
- FFmpeg，终端中能运行 `ffmpeg` 和 `ffprobe`
- CMake 3.22 或更高版本，以及支持 C++17 的编译器
- Android Studio；安卓开发还需要 SDK Platform 36、NDK `28.2.13676358`、CMake `3.22.1`
- 首次 Android 原生构建需要联网下载约 20 MiB 的 ncnn `20260526` Android 包；CMake 会校验固定 SHA-256 并缓存到忽略的 `.cxx` 构建目录

macOS 可通过 Homebrew 安装桌面依赖：

```sh
brew install python ffmpeg cmake
```

克隆仓库后创建独立 Python 环境：

```sh
git clone <仓库地址>
cd wujie_hackathon
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e '.[test]'
```

Windows PowerShell 激活环境使用：

```powershell
py -3.10 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -e ".[test]"
```

确认 Python 工具可用：

```sh
python -m pytest -q
python -m mapassist.annotation_server --help
```

参与现有标注的同伴只需打开主机提供的网址。需要本地处理录像的开发者，应由数据负责人通过团队认可的私密渠道取得所需目录，并保持原有相对路径。不要把私有素材放入 Git 提交、聊天附件或公开网盘。

公开源码的默认 profile 会关闭小地图识别器，因此干净克隆可以构建和启动应用，不会尝试加载私有权重。获准本机运行 YOLOX 实验时，把 v2 的 `minimap-yolox-nano-320.param` 与 `minimap-yolox-nano-320.bin` 放到 `android/app/src/main/assets/`；保留仓库自带的 `.metadata.json`，构建会校验本地文件的 SHA-256。然后在应用中导入 `profiles/hok_minimap_hd_bootstrap.android.json`，并主动开启“允许未通过真人录像评测的实验识别器”。缺少权重时该实验配置会给出模型文件缺失提示；不要将权重添加到 Git。YOLOX 实际启用时，运行时会比对 profile 的 `models.minimap_yolox_bin_sha256` 与 APK metadata 中的 ncnn bin SHA-256；缺失或不匹配时会拒绝启动识别器。该 v2 候选的严格 parity 尚未通过，只能用于本机开发测试。

忽略规则和从当前 Git 索引移除模型文件，不会清理既有提交中的副本。当前 GitHub 仓库已公开，旧提交 `e887714` 仍包含这两个模型文件。若团队要求从公开历史彻底移除，需先确认改写历史与 force-push，并通知所有协作者重新同步；本次只移除当前索引内容，不改写历史。

## Android 开发构建与真机试装

在 Android Studio 中选择 **Open** 并打开仓库的 `android/` 目录，等待 Gradle Sync 完成；若提示缺少组件，通过 SDK Manager 安装 SDK Platform 36、NDK `28.2.13676358` 和 CMake `3.22.1`。连接开启 USB 调试的 Android 手机，在手机上确认此电脑的调试授权。Android Studio 的 Run 可直接构建、安装并启动应用。

本机开发 profile 需要私有的 v2 `minimap-yolox-nano-320.param` 与 `.bin`，放在 `android/app/src/main/assets/`；Git 忽略这些模型文件，构建会按仓库 metadata 校验哈希。缺少任一文件时先按团队认可的私密渠道准备匹配文件，不要将它们提交到 Git。

在 macOS 或 Linux 的 Bash 中，可从仓库根目录一键构建并安装开发 APK：

```sh
bash scripts/install_android_debug.sh
```

脚本会定位 Android Studio JBR、Android SDK 和 adb，运行 `testDebugUnitTest` 与 `assembleDebug`，检查设备已授权、API 不低于 29 且支持 `arm64-v8a`，安装 `app-debug.apk`，把实验 profile 推送到手机 Download 目录，并启动应用。默认只接受恰好一台已授权设备；多台设备时先用 `adb devices -l` 查看序列号，再指定：

```sh
bash scripts/install_android_debug.sh --serial '<设备序列号>'
```

Android 11 及更高版本也可用 Wi-Fi ADB：让手机和电脑接入同一网络，在手机 **开发者选项 → 无线调试** 中选择“使用配对码配对设备”，在电脑运行 `adb pair '<IP>:<配对端口>'`，并只在 adb 提示时输入手机显示的配对码。配对码不要写进命令或脚本。若 `adb` 不在 PATH 中，用 Android SDK 的 `platform-tools/adb` 完整路径运行配对命令。配对完成后，查看无线调试主页面显示的 **IP 地址和连接端口**（它与配对端口不同），运行：

```sh
bash scripts/install_android_debug.sh --connect '<IP>:<连接端口>'
```

脚本会先运行 `adb connect`，再确认这台设备已授权后安装。若连接失败，重新检查无线调试页面的连接端口和网络状态。

该脚本只做开发试装，不会自动导入配置、勾选实验开关或请求 MediaProjection。安装后依次进入 **“王者荣耀” → “配置与调参” → “导入配置文件”**，选择 Download 里的 `hok_minimap_hd_bootstrap.android.json`，再手动开启 **“启用实验识别器”**。导入 JSON 只更换 profile，不会复制权重。不要导入 `profiles/hok_minimap_development.android.json` 或旧自适应 profile；它们绑定已退役的低清模型。不得在 video9/12 运行模型或查看预测。

### 手机授权与基本操作

1. 在允许的练习场景中使用。点 **“授权截屏并开始”**。Android 13 及更高版本首次会先请求通知权限：允许后再点一次开始；若此前拒绝，到系统设置中为“听野”开启通知。
2. 在系统 MediaProjection 对话框中选择 **共享整个屏幕**，确认开始共享。每次新截屏会话都需要重新授权；不要选择单应用共享。
3. 授权后切回游戏练习场景并转为横屏。通知显示 **“正在处理画面”** 表示已进入横屏采集；显示 **“等待横屏”** 时，转动手机到横屏并确认系统自动旋转未锁定。
4. 需要暂停时，从屏幕顶部下拉通知栏，在“听野”持续通知上点 **“暂停”**；恢复时点 **“继续”**。暂停会暂停帧处理和提示，不要在用于连续 15 分钟处理指标的时段暂停。
5. 结束时下拉通知栏并点 **“停止”**。确认持续通知消失；如果只想暂停提示，不要误点停止。主界面也有暂停和停止按钮。

此开发 APK 内置 profile 默认关闭检测器；导入上述实验 profile 后才可用实验开关启用。该候选仍为 `verified=false`、`release_ready=false`，且严格 ncnn parity 未通过，故此流程只用于开发试装和问题记录，不代表正式验收或可发布版本。

正式机器验收另走[最终门禁流程](../validation/SESSION_TEMPLATE.md)：它要求未来构建一个把冻结 profile 和匹配模型内置的 APK，并以该固定 APK 完成真机会话。当前开发脚本会导入实验 profile，因此不能用它替代最终门禁的冻结构建与安装流程。

不要直接导入 `profiles/hok_minimap_adaptive.experimental.android.json`。该旧自适应 profile 绑定 dense baseline checkpoint `68b86a7a10c97d9b2c738f72b1f49a0b1dcc76d10751ee9f4e61380ee4fb93bc`，与已退役的 hard-FP checkpoint `f7176b7ea9de65fb0f1fe4262514992fdda2ed8691a7a87851a2d27a910c7cfb` 不是同一模型，混用会让 profile 与 ncnn 权重不匹配。旧本机候选使用固定 ROI profile，但其 ROI 和权重都未按新测得的小地图边界校正，现已退役；自适应定位的实现、旧对照和限制见[小地图自动定位器验证记录](../validation/MINIMAP_LOCATOR.md)。

开发排查时可用 `adb logcat -c` 清空旧日志，再持续保存 `MapAssistCapture` 日志；正式证据采集的完整步骤见[真机会话模板](../validation/SESSION_TEMPLATE.md)。每次启动会输出唯一 `SessionStart sessionId=...`；不要拼接多次启动的日志或手填 cue ID。

修改默认开发配置后重新生成 Android 文件：

```sh
PYTHONPATH=python python3 -m mapassist.bundle_profile \
  profiles/hok_minimap_hd_bootstrap.json \
  --output profiles/hok_minimap_hd_bootstrap.android.json
```

重新生成自动定位描述符和 Android 实验配置时，只能使用人工复核的开发对局；独立留出录像不能参与校准：

```sh
PYTHONPATH=python python3 -m mapassist.calibrate_minimap_anchor \
  data/private/minimap-review-v4-dense/review-manifest.json \
  --output build/minimap-locator-dev.json
```

将生成的 JSON 放入桌面 profile 的 `layout.minimap_locator` 后，再运行 `mapassist.bundle_profile`。定位层可用 `mapassist.minimap_locator_evaluate` 单独回放，命令见验证记录。

## 日常协作约定

- 从 `main` 拉出短分支，提交前同步最新 `main`。
- 不提交录像、玩家信息、数据库、私有配置、密钥或本机构建物。
- 修改识别规则时写明使用了哪些对局；用过的对局不能再声称是独立留出数据。
- 提交前运行 `python -m pytest -q`；安卓改动再运行 `./gradlew assembleDebug lintDebug`。
- 发布前运行 `python3 scripts/check_public_repo.py`，并完成 [GitHub 发布检查清单](GITHUB发布检查清单.md)。
