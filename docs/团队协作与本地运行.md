# 团队协作与本地运行

本文给第一次接手项目的同组成员使用。所有命令默认在仓库根目录执行。

## 最快开始：参与小地图标注

标注服务只需由一台电脑启动。其他同伴在同一可信 Wi-Fi 下直接用浏览器打开局域网地址，不需要克隆仓库，也不要各自复制数据库后同时标注。

主机执行：

```sh
source .venv/bin/activate
PYTHONPATH=python python3 -m mapassist.annotation_server \
  --dataset minimap-layout=data/private/minimap-layout-review-v1/queue \
  --dataset minimap-layout-video8=data/private/minimap-layout-video8-v1/queue \
  --dataset dense-v1-6=data/private/minimap-review-v4-dense \
  --dataset expanded-video7=data/private/minimap-review-v6-video7-expanded \
  --dataset holdout-video7=data/private/minimap-video7-holdout-v1 \
  --dataset video8-v3=data/private/minimap-video8-holdout-v1/blind-review-v3-safe-roi \
  --dataset video1-hd=data/private/minimap-review-video1-hd-v1 \
  --dataset reviewed-v1-5=data/private/minimap-review-v3 \
  --dataset reviewed-v6=data/private/holdout-video6/blind-review \
  --host 0.0.0.0 --port 8765
```

终端会打印类似 `http://192.168.1.20:8765/` 的地址。把这个地址发给同一网络中的同伴，每人输入不同的标注员名字。网页顶部可以在 video1-hd、video7、video8-v3 和历史队列间切换，全部共用一个 `8765` 端口；各队列的数据库和清单分别保存。网站没有账号和访问控制，只能在可信局域网内使用，不能映射到公网。

单人在主机上标注时可自动打开浏览器：

```sh
PYTHONPATH=python python3 -m mapassist.annotation_server \
  --dataset minimap-layout=data/private/minimap-layout-review-v1/queue \
  --dataset minimap-layout-video8=data/private/minimap-layout-video8-v1/queue \
  --dataset dense-v1-6=data/private/minimap-review-v4-dense \
  --dataset expanded-video7=data/private/minimap-review-v6-video7-expanded \
  --dataset holdout-video7=data/private/minimap-video7-holdout-v1 \
  --dataset video8-v3=data/private/minimap-video8-holdout-v1/blind-review-v3-safe-roi \
  --dataset video1-hd=data/private/minimap-review-video1-hd-v1 \
  --dataset reviewed-v1-5=data/private/minimap-review-v3 \
  --dataset reviewed-v6=data/private/holdout-video6/blind-review \
  --host 127.0.0.1 --port 8765 --open
```

停止服务按 `Ctrl+C`。每个队列的进度保存在其目录下的 `annotations.sqlite3`，重启同一命令会继续原进度。数据库使用 WAL 和 15 分钟任务租约；不要在服务运行时手工编辑 `review-manifest.json` 或复制数据库。

### 标注规则

先看完整画面，确认当前是对局中的 HUD。准备、选人、加载、结算等画面使用 `excluded`，不要标成没有敌人的 `negative`。

| 状态 | 什么时候使用 |
| --- | --- |
| `accepted` | 自动建议框完整且位置正确 |
| `corrected` | 删除错框、移动框或补全漏掉的小地图敌人后保存 |
| `negative` | 对局中画面，确认小地图上没有该类敌人目标 |
| `excluded` | 准备、选人、加载、结算等非对局界面 |
| `skip` | 画面模糊、遮挡严重或无法确定 |

### video1-hd 高清迁移队列

`video1-hd` 指向 `data/private/minimap-review-video1-hd-v1`，包含 100 张完整 `2400×1080` 帧。新文件与旧 video1 是同一场对局，但画面布局发生了缩放和平移；旧归一化框不能原样复制。队列用 8 个跨全片配对帧得到的仿射变换生成 133 个绿色建议框，所有任务仍从 `pending` 开始，建议框不是真值，也不能按 `A` 直接接受。

小地图方向参考范围为归一化 `widget_roi=[0.0526544476,0,0.1406481970,0.3095749823]`，检测安全裁剪为 `roi=[0.0369044476,0,0.1721481970,0.3442777601]`。只框中心位于 widget 内的红圈敌方英雄；蓝圈队友、建筑、兵线、信号和控件外 HUD 头像不框。每张图必须逐框检查后按 `C`，无敌人按 `N`，非对局或无法判读的全屏遮挡按 `E`。`281.333s` 附近的时间匹配不唯一，遇到该时段必须查看前后帧。

来源、时间对齐精度和清晰度测量见 [video1 高清记录](../validation/VIDEO1_HD.md)。

### video8-v3 安全 ROI 敌人队列

当前队列为 `data/private/minimap-video8-holdout-v1/blind-review-v3-safe-roi`，与 v1 使用相同的 120 个时间点。发现首轮坐标转换错误后已全部重标并独立审计，结果为 102 张 `corrected`／211 框、17 张 `negative`、1 张 `excluded`、0 张 `pending`。帧和标注叠图都是完整横屏尺寸 `2376×1080`。

小地图控件范围是 `[106,0,454,344]`。模型输入使用向外加 27 px 安全边距的裁剪 `[79,0,481,371]`，尺寸 `402×371`，全屏归一化 ROI 为 `[0.03324915824915825,0,0.1691919191919192,0.3435185185185185]`。安全边距只用于保留上下文：**只标注图标中心位于小地图控件内的敌方英雄；安全裁剪范围内但控件外的 HUD 头像不标。**

旧队列 `blind-review-v2-roi-recalibrated` 的帧是 `348×344` crop，manifest ROI 却仍是全屏坐标，当前无效且不能启动。请使用上面的 `video8-v3` 启动项；v3 已导出安全 ROI COCO 并完成同场开发诊断，尚未据此重训敌人检测器。

快捷键：`A` 接受建议框、`C` 保存当前框、`N` 负样本、`E` 非对局画面、`S` 跳过、`Z` 切换放大/完整画面、`R` 恢复建议框、`Delete` 删除选中框、`Enter` 领取下一张。拖动空白处新增框，拖动已有框移动，拖动右下角圆点缩放。暂时离开时点击“释放任务”。

### 小地图边界队列

`minimap-layout` 和 `minimap-layout-video8` 用来训练小地图区域定位器。每张图只保留一个框，把它调整到小地图可见外边界，然后按 `C` 保存。绿色框只是旧固定 ROI 建议，必须人工检查；准备、加载、结算等非对局画面按 `E`。两个队列共有 128 张／128 个边界框。video8 的 16 个初始边界框后来发现左缘有误，已重校；使用旧边界的 v1 video8 覆盖率／IoU 已作废。定位器 v2 已按修正边界重训，但 video8 只用于布局开发诊断，不作为独立布局测试；评测数据和哈希见[定位器验证记录](../validation/MINIMAP_LOCATOR.md)。

需要从源清单重建时执行；协作标注开始后不要重跑：

```sh
PYTHONPATH=python python3 -m mapassist.minimap_layout_review_dataset \
  data/private/minimap-layout-review-v1/source-manifest.json \
  --output data/private/minimap-layout-review-v1/queue \
  --samples-per-match 16
```

定位器 v2 按整场录像划分为 112 张 train（video1–5、video7、video8；含 video8 的 16 张修正边界帧）和 16 张 video6 val。另 120 张 video8 布局评测帧本身未用于训练，但与 train 中的 16 张同属一场对局，因此只能作为 same-match development diagnostic，不能称为独立测试或诚实留出。video6 val 用于模型／置信度选择，也属于开发验证。详细指标和 SHA-256 见 [`validation/MINIMAP_LOCATOR.md`](../validation/MINIMAP_LOCATOR.md)。

### 外部公开数据

Roboflow 小地图、英雄和场景数据以及 KPL 公开视频只作为候选预训练／困难样本语料。下载前后的来源登记、类别映射、重复检查和 COCO 自动审计命令见[外部数据引入与预训练](外部数据引入与预训练.md)。128 个数字类在语义未确认前不能直接合并成 `minimap_enemy`，公开数据的图片级划分也不能替代自录整场对局验证。

### 新的密集开发队列

`dense-v1-6` 从六场录像的有效对局区间各均匀抽取 100 张，共 600 张。抽样不读取任何检测结果，避免继续只收集旧规则容易识别的红圈。这个队列没有建议框，因此禁用 `A`：有敌人时逐个框出完整头像后按 `C`，确认没有敌人时按 `N`，准备、选人、加载、展开大地图和结算画面按 `E`。

该队列现已完成：497 张正样本、76 张负样本、27 张排除帧，共 865 个敌人框。与旧标注合并后的训练清单为 749 张／1,143 框。网站仍可用于查看结果，新成员无需重复标注这 600 张。

现有六场录像及其标注都已经参与开发，不能再作为最终留出成绩。`reviewed-v6` 保留原盲测过程和历史结果，但现在只作为开发数据使用。

重建密集队列的命令是：

```sh
PYTHONPATH=python python3 -m mapassist.uniform_review_dataset \
  data/private/expanded/minimap-dense-source.json \
  --output data/private/minimap-review-v4-dense \
  --samples-per-match 100
```

不要在已经开始协作标注后重跑这条命令，以免覆盖队列清单。

### video7 扩展开发队列

`expanded-video7` 新增 240 张 2712×1220 标注帧。抽样仍不读取模型预测，并排除旧 video7 队列每个时间点前后 1 秒；实际最近间隔为 2.552 秒，因此不是旧标签的近邻重复。队列已完成：186 张 `corrected`、33 张 `negative`、16 张 `excluded`、5 张 `skip`，共 334 个框；结果来自 AI 辅助初标与交叉审计，仍建议队友抽查困难样本。

网页会显示低阈值模型建议框，213 张图有建议，共 442 个框；这些框只是加快操作的起点。此队列禁用 `A`，标注员必须逐图检查：删掉友方头像等错框、补齐漏框、调整边界后按 `C`；确认没有敌人按 `N`，非对局画面按 `E`。即使建议框看起来正确，也要人工看完后按 `C` 明确确认。

复建命令如下；已开始标注后不要重跑：

```sh
PYTHONPATH=python python3 -m mapassist.uniform_review_dataset \
  data/private/minimap-video7-expanded-source.json \
  --output data/private/minimap-review-v6-video7-expanded \
  --samples-per-match 240 \
  --exclude-manifest data/private/minimap-video7-expanded-exclusions.json \
  --exclude-gap-ms 1000
```

原始预测无关队列清单 SHA-256 为 `93841144694fa06f38b8836909ba3638737a567a473b4672a692e01f2de05231`。附加建议后的当前清单 SHA-256 为 `94363bb38528e54d835a1e519d662eade9a25be6c54445b3749f5c90a2e69508`。全部帧已经核对为 2712×1220 实际横屏像素且不带 EXIF 旋转；标注网站可正常读取 240 个任务。

当前建议使用冻结 ONNX 模型 `5072feba…e32`，置信度 `0.10`、NMS `0.5`；预标注文件 SHA-256 为 `bad70fe6…a0ba`。选择帧发生在生成建议之前，清单继续记录 `predictions_used_for_selection=false`。需要从原始队列复现时，在任何协作标注开始前执行：

```sh
PYTHONPATH=python .venv/bin/python training/prelabel_review_queue.py \
  data/private/minimap-review-v6-video7-expanded/review-manifest.json \
  --model build/models/minimap-yolox-nano-dense-320/model.onnx \
  --output build/prelabels/video7-expanded-v1 \
  --input-size 320 --confidence 0.10 --nms-threshold 0.5

PYTHONPATH=python:. .venv/bin/python training/attach_review_suggestions.py \
  data/private/minimap-review-v6-video7-expanded/review-manifest.json \
  build/prelabels/video7-expanded-v1/prelabels.json
```

附加后重启标注网站，使 SQLite 任务表读取新建议。不要在同伴已经开始标注后更换建议模型或阈值。

### 新录像质量要求

现有录像只有 720×324 或 960×432，视频码率约 0.53–0.99 Mbps；裁出的小地图通常仅 104×108，最小敌人头像宽度约 6 像素。新录像请优先使用手机原生横屏分辨率和录屏的“高画质／高码率”设置；1080p、30 FPS 可先以 8–12 Mbps 为目标。录完先运行：

```sh
ffprobe -v error -select_streams v:0 \
  -show_entries stream=width,height,avg_frame_rate,bit_rate \
  -of default=nw=1 video/新录像.mp4
```

不要把完整画面预先压到 720p 再交给标注或模型。数据导出和安卓推理都应从原始整帧直接裁小地图，再缩放到模型输入尺寸。

`video7.mp4` 已按这一要求录成 2712×1220、30 FPS、约 8 Mbps，证明高分辨率能显著改善人工辨认，但冻结盲测仍只有 65.57% precision / 63.49% recall。它现已降级为开发数据，并建立上面的扩展队列。下一份素材应优先录新的真实匹配对局；用于开发还是登记为未调参 test，必须在看预测前决定。

## 首次安装开发环境

### 必需软件

- Python 3.10 或更高版本
- FFmpeg，终端中能运行 `ffmpeg` 和 `ffprobe`
- CMake 3.22 或更高版本，以及支持 C++17 的编译器
- Android Studio；安卓开发还需要 SDK Platform 36、NDK `28.2.13676358`、CMake `3.22.1`
- 首次 Android 原生构建需要联网下载约 20 MiB 的 ncnn `20260526` Android 包；CMake 会校验固定 SHA-256 并缓存到忽略的 `.cxx` 构建目录

macOS 可通过 Homebrew 安装桌面依赖：

```sh
brew install python ffmpeg cmake
```

克隆仓库后创建独立 Python 环境：

```sh
git clone <仓库地址>
cd wujie_hackathon
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e '.[test]'
```

Windows PowerShell 激活环境使用：

```powershell
py -3.10 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -e ".[test]"
```

确认 Python 工具可用：

```sh
python -m pytest -q
python -m mapassist.annotation_server --help
```

### 私有素材不会随 GitHub 仓库下载

公开仓库不会包含以下内容：

- `video/` 中的原始游戏录像；
- `data/private/` 中的标定配置、抽帧、预测、人工标注和 SQLite 数据库；
- `data/raw/` 中的原始数据，包括 Roboflow 图片和导出副本；
- 模型权重、训练检查点和其他训练产物；
- APK、原生库及其他构建物；
- 未确认公开授权的题方资料。

参与现有标注的同伴只需打开主机提供的网址。需要本地处理录像的开发者，应由数据负责人通过团队认可的私密渠道取得所需目录，并保持原有相对路径。不要把私有素材放入 Git 提交、聊天附件或公开网盘。

公开源码的默认 profile 会关闭小地图识别器，因此干净克隆可以构建和启动应用，不会尝试加载私有权重。获准本机运行 YOLOX 实验时，把 `minimap-yolox-nano-320.param` 与 `minimap-yolox-nano-320.bin` 放到 `android/app/src/main/assets/`；保留仓库自带的 `.metadata.json`，构建会校验本地文件的 SHA-256。然后在应用中导入 `profiles/hok_minimap_development.android.json`，并主动开启“允许未通过真人录像评测的实验识别器”。缺少权重时该实验配置会给出模型文件缺失提示；不要将权重添加到 Git。YOLOX 实际启用时，运行时会比对 profile 的 `models.minimap_yolox_bin_sha256` 与 APK metadata 中的 ncnn bin SHA-256；缺失或不匹配时会拒绝启动识别器。

忽略规则和从当前 Git 索引移除模型文件，不会清理既有提交中的副本。当前 GitHub 仓库已公开，旧提交 `e887714` 仍包含这两个模型文件。若团队要求从公开历史彻底移除，需先确认改写历史与 force-push，并通知所有协作者重新同步；本次只移除当前索引内容，不改写历史。

## 查看标注进度与收口

服务运行时查看团队进度：

```sh
curl -fsS http://127.0.0.1:8765/api/stats
```

标注尚未完成时，可生成阶段诊断：

```sh
PYTHONPATH=python python3 -m mapassist.detection_evaluate \
  data/private/minimap-review-v3/review-manifest.json \
  --allow-pending \
  --output data/private/minimap-review-v3/detection-report.partial.json
```

阶段报告带有 `PARTIAL REPORT` 标记，不能作为正式成绩。全部样本完成后，先停止标注网站，再依次运行：

```sh
PYTHONPATH=python python3 -m mapassist.detection_evaluate \
  data/private/minimap-review-v3/review-manifest.json \
  --output data/private/minimap-review-v3/detection-report.json
cmake -S native -B build/native -DCMAKE_BUILD_TYPE=Release
cmake --build build/native --parallel
PYTHONPATH=python python3 -m mapassist.detection_replay_evaluate \
  data/private/minimap-review-v3/review-manifest.json \
  --profile profiles/hok_minimap_development.json \
  --output data/private/minimap-review-v3/detection-report-current.json
PYTHONPATH=python python3 -m mapassist.finalize_review \
  data/private/minimap-review-v3/review-manifest.json \
  --output data/private/minimap-review-v3/detection-manifest.json
PYTHONPATH=python python3 -m mapassist.detection_dataset \
  data/private/minimap-review-v3/detection-manifest.json \
  --output data/private/minimap-review-v3/coco
```

`detection-report.json` 评估队列生成时保存的原始建议框；`detection-report-current.json` 会用当前原生库重新处理同一批人工真值帧，适合检查代码修改是否真实改善。当前 `video1` 至 `video6` 都参与过开发，只用于改进检测器。最终完整对局事件成绩必须来自另一场未参与调参、时间轴连续的新对局。

## 打开和构建安卓应用

1. 打开 Android Studio，选择 **Open**，打开仓库中的 `android/` 目录。
2. 等待 Gradle Sync 完成。若提示缺少组件，通过 SDK Manager 安装 SDK Platform 36、NDK `28.2.13676358` 和 CMake `3.22.1`。
3. 连接开启 USB 调试的 Android 13/14 手机，在 Android Studio 设备列表中选择手机并点击 Run。

macOS 也可从命令行构建：

```sh
cd android
export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"
export ANDROID_HOME="$HOME/Library/Android/sdk"
./gradlew assembleDebug lintDebug
cd ..
```

APK 位于 `android/app/build/outputs/apk/debug/app-debug.apk`。当前只构建 `arm64-v8a`。本机开发 APK 使用 `android/app/src/main/assets/minimap-yolox-nano-320.param` 和 `.bin`；模型文件由 Git 忽略，构建前须在本机准备好，tracked metadata 会校验它们的 SHA-256。连接手机后安装：

```sh
adb devices -l
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
```

APK 默认 profile `android/app/src/main/assets/profile.json` 的 `verified` 和 `detectors.minimap_yolox` 均为 `false`。本机固定 ROI 开发 profile `profiles/hok_minimap_development.android.json` 指向 hard-FP checkpoint `f7176b7ea9de65fb0f1fe4262514992fdda2ed8691a7a87851a2d27a910c7cfb`，confidence `0.19`、NMS `0.5`；它仍是未验证开发候选。该 legacy fixed ROI 已发现会截掉小地图右缘，video6 指标只适用于旧裁剪范围，不能表示完整地图覆盖。修正 ROI 后须按新裁剪重训；不要直接扩大当前运行时 ROI 并沿用现有权重。只勾实验开关不会覆盖默认 profile 的 `minimap_yolox: false`，因此不会运行模型。

在本机导入已更新的固定 ROI 开发 profile：

```sh
adb push profiles/hok_minimap_development.android.json /sdcard/Download/
```

然后在应用中选择“导入配置”，载入 Download 目录里的 JSON；勾选“允许未通过真人录像评测的实验识别器”，再重启截屏会话。运行前还需确认 APK 中存在匹配 metadata SHA-256 的 ignored param／bin。导入 JSON 只更换 profile，不会复制权重。点击“授权截屏并开始”，每次会话都选择共享整个屏幕。首次真机测试使用允许的练习场景，并按[真机会话记录模板](../validation/SESSION_TEMPLATE.md)记录至少 15 分钟的实际发声、游戏音频、帧率和发热表现。

不要直接导入 `profiles/hok_minimap_adaptive.experimental.android.json`。该旧自适应 profile 绑定 dense baseline checkpoint `68b86a7a10c97d9b2c738f72b1f49a0b1dcc76d10751ee9f4e61380ee4fb93bc`，与当前 hard-FP checkpoint `f7176b7ea9de65fb0f1fe4262514992fdda2ed8691a7a87851a2d27a910c7cfb` 不是同一模型，混用会让 profile 与 ncnn 权重不匹配。当前本机候选使用固定 ROI profile，但其 ROI 和权重都未按新测得的小地图边界校正；自适应定位的实现、旧对照和限制见[小地图自动定位器验证记录](../validation/MINIMAP_LOCATOR.md)。

正式真机验收前先执行 `adb logcat -c`，并把 `MapAssistCapture` 日志从授权前一直保存到通知栏停止之后。每次启动会输出唯一 `SessionStart sessionId=...`；不要拼接多次启动的日志或手填 cue ID。完整采集、解析、外部录像标注和门禁命令都在上述真机会话模板中。

修改默认开发配置后重新生成 Android 文件：

```sh
PYTHONPATH=python python3 -m mapassist.bundle_profile \
  profiles/hok_minimap_development.json \
  --output profiles/hok_minimap_development.android.json
```

重新生成自动定位描述符和 Android 实验配置时，只能使用人工复核的开发对局；独立留出录像不能参与校准：

```sh
PYTHONPATH=python python3 -m mapassist.calibrate_minimap_anchor \
  data/private/minimap-review-v4-dense/review-manifest.json \
  --output build/minimap-locator-dev.json
```

将生成的 JSON 放入桌面 profile 的 `layout.minimap_locator` 后，再运行 `mapassist.bundle_profile`。定位层可用 `mapassist.minimap_locator_evaluate` 单独回放，命令见验证记录。

## 日常协作约定

- 从 `main` 拉出短分支，提交前同步最新 `main`。
- 不提交录像、玩家信息、数据库、私有配置、密钥或本机构建物。
- 修改识别规则时写明使用了哪些对局；用过的对局不能再声称是独立留出数据。
- 提交前运行 `python -m pytest -q`；安卓改动再运行 `./gradlew assembleDebug lintDebug`。
- 发布前运行 `python3 scripts/check_public_repo.py`，并完成 [GitHub 发布检查清单](GITHUB发布检查清单.md)。
