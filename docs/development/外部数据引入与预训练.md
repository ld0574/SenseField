### Honor of Kings Minimap 实际审计与预训练结论

审计下载包的 COCO 标注得到 train 2,989 张／16,346 框、valid 4 张／20 框，128 个类别名称均为数字；包内没有 test split。对图片文件计算内容哈希后，未发现重复图片。Roboflow 导出的图像经过 `Stretch640` 拉伸到 640×640，不能用于真实 HUD 几何或长宽比评估。审计及后续整理没有使用 `heroes` 父类标签；通用头像预训练时将 128 个数字类合并为单一 `minimap_hero` 类，避免把没有语义说明的数字误当作英雄身份或敌我标签。

在自录 video1–6 开发训练／验证集上，使用相同 320 输入、训练划分和验证选择流程做了两次公平微调对照。自录数据基线为 precision 90.50%、recall 72.65%、F1 80.60%；通用 `minimap_hero` 预训练初始化的 v1 为 90.30% / 66.82% / 76.80%，v2 为 90.51% / 64.13% / 75.07%。两次外部初始化的 F1 均低于基线，v2 的 precision 略高但 recall 明显更低，因此当前不替换基线模型。以上均为开发验证结果，不是独立留出成绩。

另做了基于图标边缘颜色的保守红圈伪标签。对每个已标注头像框计算红、绿、蓝环颜色分数，要求红环分数至少 0.04 且比次高颜色至少高 1.5 倍；一张图中只要有一个图标颜色不明确，就排除整张图。明确红环头像转为 `minimap_enemy` 正框，明确绿／蓝头像作为确认负例且不生成框。这是由像素颜色推断敌我关系的启发式，不是数据集提供的队伍真值。

红圈处理在 train 中保留 986 张（655 张含红圈目标、331 张无红圈目标），排除 2,003 张含歧义图像，产生 1,373 个敌人框；valid 的 4 张中仅保留 1 张和 4 个框，另外 3 张因歧义排除。极小的外部 valid 只供训练流程使用，不能作为成绩或选模证据。红圈伪标签只进入开发预训练；正式 holdout 的录像、标签和冻结预测不变。

**红圈预训练微调结果：**在与自录基线相同的 video1–6 开发训练／验证划分上，best epoch 20、confidence 0.63 时 precision 90.36%、recall 67.26%、F1 77.12%。基线为 90.50% / 72.65% / 80.60%，红圈初始化相差 -0.14 / -5.39 / -3.48 个百分点，未超过基线，因此不替换基线。两次微调的训练与验证标注哈希及关键训练参数相同；这仍是参与选模和阈值选择的开发验证结果，不是正式留出成绩。完整对照参数和 checkpoint SHA-256 见[外部数据验证记录](../../validation/EXTERNAL_PRETRAINING.md)。

原始外部图片、下载标注、转换后的图像、模型权重及训练产物都保留在 `.gitignore` 覆盖的本地数据／构建目录，不提交到仓库。若未来确需分发模型或数据，先评估上游素材权利，并按 CC BY 4.0 补齐署名、许可证链接和修改说明；许可证标记不等于游戏画面的权利授权。

## 导入门禁

外部数据只有同时满足以下条件才可进入训练：

1. 保存来源 URL、版本、下载日期、页面所示许可证和下载包 SHA-256；
2. 找到可读的类别语义，确认哪些框能映射为本项目的 `minimap_enemy`；数字类别不能直接全部合并为敌人；
3. 检查同图重复、相邻视频帧和跨 split 重复；重新按来源视频／对局分组，而非随机按图片拆分；
4. 保持原始宽高比。页面已经拉伸到 640×640 的版本只能用于预训练对照，不能用于测量真实手机 HUD 几何；
5. 抽查至少每类 20 个框，记录错标、漏标、友敌混淆和非游戏界面；
6. 外部验证集指标只作数据质量参考，不进入比赛验收结论。

## 私有下载和自动审计

通过 Roboflow 网页或团队账号下载 COCO 格式，解压到忽略目录。API key 只放在本机环境变量中，不写入命令历史、文档或 Git：

```text
data/raw/external/
└── honor-of-kings-minimap-v1/
    ├── annotations/
    ├── train2017/
    ├── val2017/
    └── test2017/
```

下载后先运行只读审计：

```sh
PYTHONPATH=python python3 -m mapassist.coco_dataset_audit \
  data/raw/external/honor-of-kings-minimap-v1 \
  --output build/external-audit/honor-of-kings-minimap-v1.json
```

报告会列出类别、各 split 的图片和框数量、分辨率、缺失文件、精确重复图片和跨 split 污染。`training_blockers` 非空时不得直接合并训练。

## 训练顺序

1. **定位器：**继续使用自录全屏和人工 `minimap_region` 边界。公开小地图裁剪图不能训练全屏位置定位器。
2. **表征预训练：**本次仅将 128 个数字类折叠为一个 `minimap_hero` 类，或用红圈启发式生成开发用 `minimap_enemy` 伪标签；外部 valid 不用于报告成绩。
3. **二分类微调：**使用自录玩家 POV，把边框颜色、阵营关系和遮挡后的完整图标人工映射为 `minimap_enemy`，再微调现有 YOLOX Nano。
4. **伪标注：**对获准使用的公开视频低阈值推理，人工复核后才进入开发集；未复核预测不作为真值。
5. **最终验证：**使用全新的真人匹配录像和 Android 实体机。5–10 台设备可作为扩展目标；黑客松首轮先覆盖至少两种宽高比和 Android 13/14 各一台，再逐步扩大。

所有外部数据、抽帧和权重默认留在忽略目录。若比赛交付需要发布权重，先把使用过的来源、许可证、修改和署名补入 `THIRD_PARTY_NOTICES.md`。
