# 消消乐元素证据与扩展

实时和截图推荐使用同一条 `Match3Sampler.samplePosition()` 链路。颜色采样仍用于旧工具的外观／空位读取，不授予实时推荐的动物身份或交换权限。

## 三份独立结论

1. **身份**：已人工核对的普通动物中心外观或家族形状，使用既有误差／分差预算。低细节、冲突身份和未知外观弃权；不能从自定义模板名称取得玩法。
2. **交换与覆盖**：当前完整格子的 16×16 外观单独与带明确普通动物规则的整格参照核验。包含外围与四个区域，不能用中心脸替代。允许小幅整体位置对齐；被对齐排除的当前像素必须是原棋盘背景域，不能排除覆盖物或棋子细节。没有完整外观证据时保存动物颜色，`SwapPermission.UNKNOWN`、覆盖层未知；推荐矩阵为 `#`，不作端点、不补三连、不算确定任务收益。
3. **收益**：继续要求当前合法交换、形成的连线及对应目标／障碍规则有证据。未知玩法只排除相关格子，可靠区域继续推荐。

同帧扩展的参照集合只取直接通过固定身份与完整外观核验的当前格子，先冻结再推断。至少两个参照提供身份支持，完整外观也需支持；推断结果、未知覆盖和新元素诊断样本都不回灌参照或固定目录。

每帧仍读取当前格子。候选中心与完整外观均逐像素相同，且冻结参照的身份／整格描述全部相同时，才复用上次推断结论；任一当前参照改变即重新计算，不靠外观哈希判断。原生故障序列将缓存结果与每帧新建采样器的完整结果逐格核对。

完整外观比较只提前结束已经超过既定误差与分差预算的候选；允许竞争的分数保持完整计算结果。背景域在构造描述时计算一次，注册仍不得抹去陌生覆盖。用完整 Manhattan 计算核对有效分数和歧义竞争者，不改 `.12`／`.025` 门槛。

## 陌生元素自动归集

`Match3UnknownElements` 仅作本地诊断。同一格的三个新鲜稳定观测才归集；重复时间不增加证据，冲突、长间隔、运动或几何变化重新计数。元素家族是暂定的会话外观身份，不表示已经认出机制。

- 每会话最多 24 个家族，每个最多两张代表样本。初始比较原型保持不变，后续只选择更清晰的代表图，不平均／训练参数。
- 原实时帧中的完整格子归一化比较；代表图为 64×64 PNG，单次复制局部格子，编码与写入使用已有共享 IO 和预算。没有新录屏源或持续截图任务。
- 图片关闭后保留类型与计数诊断，不保存局部图；已排队图片随原有图片开关代次作废。满额、IO 忙与丢弃状态分开记录，不能把没有图写成“已保存”。
- 导出的诊断 ZIP 包含 `elements/u1-1.png` 等代表图，事件中的 `Match3ElementObserved`／`Match3ElementSample` 对应会话、格子、时间、身份／权限状态和保存结果。开发者继续使用既有 ADB 自动收集，不要求玩家手工导出。
- 旋转、关卡／几何切换只重置稳定计数；家族仍限于该会话。停止后不将诊断原型加载进识别器。

同格像素与规则状态完全相同、家族原型集合没有增加时，可以复用诊断归属；像素变化、新家族、运动、几何切换或长间隔均重新核验。缓存不参与动物身份或交换权限。新家族可能使旧归属产生歧义，回归单独覆盖这项失效条件。

## 一次扩展一个家族

先检查代表图和来源画面，把“动物的新表情／普通提示光圈”“已有覆盖层”“新机制”分开。确认编号、当前覆盖和机制后，为共享家族添加少量代表外观、完整格子参照和人工标注；不用关卡号分支。

固定资产 `match3-fixed-ui-v1.json` 的普通动物中心参照和 `ordinary_envelopes` 必须显式写 `rule: ordinary_uncovered_animal`，保留来源、坐标与人工核对范围；没有标记的动物参照不进入可信集合。新障碍／特殊组合不能仅填这个标记来借用动物规则，须单独实现玩法与效果回归。

先验证混淆物、陌生覆盖、采样偏移、待机姿态、亮度、尺寸和新布局，再使用原自动门禁验证同一份最终 Release。分别报告身份漏认、错色、覆盖弃权和未知／障碍误放行为可交换动物。开发故障图、资产自身和变换的模板都是工程回归，不作独立留出正确率；独立新局、实际采纳收益、外部声音及匹配条件下的温升仍单独验收。

此流程不训练、不扫描阈值、不读取封存视频，不自动提高历史评分、`verified` 或 `release_ready`。门禁入口见 [自动回归](match3-regression.md)。

## 2026-10-10 任务关联扩展

固定目录更新为 298,565 bytes；原动物中心／整格和预算保留。新增 `large_objects` 只接收显式 `identity_only_2x2` 的人工审阅饼干外观，利用当前四格的完整描述组合核验，不从诊断归集读取素材。匹配后仅取得阻挡身份和同一物体标识；四格不可交换、层数未知，任务评分不计确定移除量。已损伤或其它未确认形状保持未知。

可靠 HUD 中的任务身份和数字是两份证据：数字为 `-1` 时仍可比较相关机会，但不能推算剩余比例、完成数或确定单位；矛盾的重复字段弃权。`goal_state.identity_supported` 与 `rule_supported` 分别记录，饼干的后者为 false。`Match3Ranking` 在稳定盘／目标变化时记录前三个候选，支持独立核对选择依据。

字形拒绝必须作用于整串数字：内部显著字形比例或高度不合格时整个计数为 `-1`，不能把 47 的 7 丢掉后接受 4。投影故障用例对照截图上的完整数量检查；步数牌选择要求原正模板与独立数字证据，数字无法通过时保留未知状态，不借旧值。

这批故障图不是独立准确率数据，也不证明金罐、特效、随机连锁或完整通关策略。结果见[三局反馈记录](../../validation/match3/MATCH3_TASK_FEEDBACK_0_4_5_2026-10-10.md)。

## 2026-10-10 独立冰层证据

第 61／62 关反馈补入共享的冰块目标身份与 `ice_surfaces`，不按关卡号判断。固定目录为 324,062 bytes，仍低于原 327,680-byte 加载上限。原 20 个动物中心、19 个普通整格参照不变；三份明确单层冰面的正例与两份普通棋盘负例竞争，沿用 `.12`／`.025` 预算。四角掩码提供静止冰层证据，不能用青色或动物中心直接断定覆盖与交换权限。目标图标与棋盘冰层分别确认。

冰面正例中的两份中性背景只用于已确认普通动物的完整外观核验：仅替换普通参照中与格边连通、且当前像素匹配冰面正例的背景。封闭眼睛、嘴部、未知前景和覆盖物保留原像素误差与四区域检查；不允许用背景归一化抹掉陌生覆盖。已确认冰层不会授予未知前景交换权，冰面动物也不进入普通无覆盖动物的同帧参照集合。背景掩码在完整计算后安全发布，避免共享目录被并行读取时看到半成品。

`iceLayers` 绑定棋盘坐标，动物互换不能搬走冰层。当前一步确定消除与潜在特效保留格沿用独立规则；理由为「消除冰层」或「优先消冰」，没有确定任务贡献时不生成这个理由。采样仍为 800ms，编码、截图频率和未知元素归集预算不变。`Match3Ranking.stationary_ice` 仅在原排序变化事件里记录紧凑网格，0 表示没有确认到冰层，不能当作独立证明该格没有冰。

第 62 关冰花机制、未通过完整外观的动物和剩余冰层仍可能弃权。实际投影后段虽然识别到 ICE 目标，当前合法推荐的确定消冰量仍为 0，不能称作该关任务策略已修好。补正家族身份与规则不等于全关卡完成，独立玩家收益继续待测。
