## 规则与视觉约束

`combo_bird_line` 从 pending 改为 partial_effect，原规则注册表仍为 68 项。只对确定、无遮挡的同色动物计算清除下界。具体转化方向和额外命中范围继续列入未知；不生成全屏确定掩码，不搜索这类未知后继，不把用户实际清到只剩一个冰面的结果写成保证。

新增 `match3-board-feedback-v1.json` 是固定的单份开发补充库，18 个描述符、33,252 字节：灰毛球 6、魔力鸟 6、花纹雪块 2、横向红狐狸 4。硬预算为 64 KiB、cell 24、ordinary envelope 4，不接收 goal、large object 或 ice surface。规则 SHA、来源 SHA 和显式 reviewed state 缺失或冲突时，只拒绝新库，保留原 gallery 和覆盖库；没有放大旧覆盖库的预算。

方向识别使用整个格子，避免 10% 内缩裁剪把身体外的箭头切掉。横向箭头有独立的侧边证据掩码，正证据误差权重为 2；整体 0.12 和竞争间隔 0.025 不变，配准仍最多一个描述符像素。整张脸、颜色、普通冰面轮廓或金色发光均不能单独赋予横向特效权限。原生批量算术与 Java 回落路径计算相同分数，原覆盖模板的权重仍为 1。

雪块边框检查改为一次读取包含原探针的矩形，复用一个采样器内的像素缓冲区，然后检查同样的三点窄条；每帧重新读取，不缓存旧边框或借用邻格权限。任一 RGB 通道达到 128 时，HSV value 必然不满足 `<0.5`，可提前排除；其余颜色仍调用 Android 的 HSV 转换。白块过滤的颜色范围和每边三点、至少两边的支持要求不变。

原实验 gallery、固定 UI、HUD glyph 和普通动物描述符保持原样。vine / gray 的修改只重新绑定本轮规则目录 SHA，旧像素和状态没有改动。诊断元数据新增 board feedback ID、SHA 和加载状态，动作证据新增 `all_targets_finish`。

策略回归还发现，仅在确定收益相同的时候偏好组合不足以稳定解决第三局：`109-403` 的冰面下界为组合 4、普通鸟换色 4，`109-405` 同一局面因另一只狐狸的特效/覆盖未知及鸟下冰面漏识，变成组合 2、普通鸟换色 3。后者会把组合的保守下界误当成它的全部价值。当前排序把有任务收益的组合机会放在单步量化进度之前，仍保留已知后继搜索、确定完成和单项完成的优先级；最后一步继续按确定收益排序。机会偏好不增加结算单位，不给未知状态交换权限，也不构造额外命中或后继。
