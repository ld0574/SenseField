# Demo 录制

使用原生 `screenrecord` 录手机画面、scrcpy 的音频模式录手机内部声音、FFmpeg 录电脑麦克风。录完自动生成混音 MP4，原始三份素材保留在 `output/video/`。

本机 Homebrew scrcpy 5.0.1 在音频录制初始化时出现过两次崩溃，栈为 `sc_recorder_audio_packet_sink_open → avformat_new_stream`。本轮独立保存官方 scrcpy 3.3.4，核对官方 SHA-256 后使用，未替换系统安装。脚本优先使用 `output/tools/scrcpy-3.3.4/scrcpy-macos-aarch64-v3.3.4/scrcpy`；其他电脑可用 `--scrcpy` 指定经过短测的可执行文件。官方安装包见 [scrcpy 3.3.4](https://github.com/Genymobile/scrcpy/releases/tag/v3.3.4)。

这台小米手机的 `playback + audio-dup` 曾在实际播报时录出纯静音，不能再用它作为验收配置。使用完整系统输出 `output`：录制期间手机声音转到电脑，停止后恢复原输出。电脑回放默认开启；建议使用电脑耳机，避免播报又被电脑麦克风收进来。

在游戏已经横屏时启动：

```sh
python3 scripts/record_android_demo.py --serial 手机无线ADB地址 --microphone 1
```

本次电脑麦克风索引为 `1`，即 MacBook Pro 麦克风。换电脑或连接新设备后，先用 `ffmpeg -f avfoundation -list_devices true -i ''` 核对索引。默认横屏尺寸为 `1920x864`，默认最多录制 30 分钟。竖屏短测可加 `--size 864x1920`。仅在无需听手机声音的受控短测中使用 `--no-monitor`。

另一终端停止：

```sh
python3 scripts/record_android_demo.py --stop
```

等待原进程完成拉取和混音后再关闭终端。`demo.mp4` 是混音成片；`phone-screen.mp4`、`phone-audio.wav`、`mac-microphone.wav` 是原始素材。`session.json` 保存状态、偏移、音源峰值和成片校验值。发现手机音轨全为零时，状态为 `stopped_phone_audio_silent`，不能把这份视频当作完整成片交付。音轨有信号仍不能证明所有播报都收到了，短测要核对可辨认的测试语句。

时间对齐使用电脑启动时钟和各音源停止时钟，属于近似同步；原生录像最后一帧可能带额外停留时长，不能直接用文件总时长推算起点。正式素材需要抽查画面变化与播报的同步。短暂的 `frame_starvation` 会保留在日志中并继续录制；辅助明确进入 `FAILED` 或 `REVOKED` 时才停止。

这些素材可能包含个人声音和游戏画面，只保存在本地，不纳入 Git。历史录制缺失的声音无法从请求状态、语音回调或截图中恢复。
