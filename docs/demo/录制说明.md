# 听野路演演示指引

## 展示顺序

1. **玩家需求**：说明有效视野有限时，玩家难以兼顾小地图、棋盘和屏幕边缘。
2. **整体方案**：展示[系统架构图](../../assets/sensefield-architecture.png)，介绍端侧识别、多通道输出与独立服务端。
3. **王者荣耀**：授权采集，展示可见敌方信息如何转成方位声音与振动。
4. **开心消消乐**：展示稳定棋盘上的亮框、箭头和方位语音，由玩家实际交换。
5. **语音与画面助手**：展示手机端语音识别、授权读图和回答播报。
6. **价值与边界**：强调减少寻找负担、保留玩家判断与操作，以及本地核心提醒和联网问答的分工。

## 演示准备

- 使用已经熟悉的手机、游戏版本和场景，提前完成安装、声音试听及必要授权。
- 手机具备可用中文 TTS；演示助手时准备网络与本地语音资源。
- 关闭个人聊天和通知展示，检查画面与声音是否清晰。
- 演示前确认游戏音量、听野语速、振动和高亮设置，保证观众能理解提示。
- 若使用预录素材，在播放时标明录制演示；现场展示与预录片段分别说明。

系统屏幕采集供识别使用，演示采录采用外部录屏或拍摄工具。真实玩家画面和原声公开前取得相应授权。

## 手机演示的固定录制方案

采用 **USB 手机连接＋电脑耳机监听＋电脑麦克风讲话**。手机画面和内部原声由固定版本 scrcpy 采集；电脑麦克风独立保存，停止后在电脑降噪和合成。手机端保持原有游戏、识别、语音功能；录制不申请另一份 Android MediaProjection 授权，也不占用手机麦克风。

耳机用于听游戏和听野播报，讲话仍由电脑麦克风收录。电脑扬声器播放游戏声音时，这些声音会再次进入麦克风；人声降噪无法可靠地区分讲话者与回录的游戏对白，因此应先解决监听路由。

固定规格为当前横屏方向、原始分辨率和 30fps 成片。源采集上限也设为 30fps，降低额外编码负担；不允许编码失败后自动缩小分辨率。静止页面可能不产生新的视频帧，实际运动流畅度还需根据源时间戳与短录画面检查，不能只看 MP4 标注的帧率。

### 依赖与保存位置

- 入口：`scripts/record_android_demo.py`，依赖 Python 3、FFmpeg、FFprobe 与 Android platform-tools。
- 固定 scrcpy **3.3.4**：从 [scrcpy 官方发布](https://github.com/Genymobile/scrcpy/releases/tag/v3.3.4)获取对应系统包，完整目录放到 `deps/demo-recorder/scrcpy-3.3.4/`，保留可执行文件、服务端文件和动态库。
- 本地 RNNoise 模型：将 [bd.rnnn](https://raw.githubusercontent.com/richardpl/arnndn-models/master/bd.rnnn) 放到 `deps/demo-recorder/bd.rnnn`。SHA-256 必须为 `ae3f7411e1e6a884f839a4a145c394408398f09854dbc1216ee02faafc98a17b`。
- 依赖、检查报告和活动状态存于被 Git 忽略的 `deps/demo-recorder/`；每次录制单独保存在被忽略的 `output/video/sensefield-demo-日期-随机标识/`。

源代码不放在可清理的成片目录。工具不自动删除原素材，也不上传音视频、截图或诊断日志。清理某次素材后，脚本会报告目录缺失；配置和脚本不能恢复已删除的录音录像。

### 每次使用

1. 手机插 USB 并授权 USB 调试；电脑插耳机，把声音输出切到该耳机。手机进入横屏游戏页面即可，检查时不用开局。
2. 检查连接、声音路由和麦克风选择，此命令仅枚举设备，不录制声音：

   ```sh
   python3 scripts/record_android_demo.py check
   ```

   默认按名称选择 `MacBook Pro麦克风`，避免设备索引变化后误选虚拟麦克风；其他设备使用 `--microphone-name "设备名称"`。多台 USB 手机使用 `--serial 序列号`。

3. 首次配置完成后先录约 15 秒，听一句用户讲话、一句手机播报，检查方向、清晰度与同步。检查通过后正式开录：

   ```sh
   python3 scripts/record_android_demo.py start --duration 1800
   ```

   命令需要保持运行。只有两路源文件均开始写入，才会显示“正在录制”；状态每五秒更新。首次短录可将时长设为 `15`，不用打一整局。

4. 在另一个终端停止或查看状态：

   ```sh
   python3 scripts/record_android_demo.py stop
   python3 scripts/record_android_demo.py status
   ```

   停止后会完成封装、降噪、合成和完整解码检查；完成状态为 `stopped_pending_quality_review`。此状态表示工程检查结束，仍应播放短片确认听感。不要在合成期间清理素材。

### 成片与异常处理

`demo-landscape-30fps.mp4` 默认播放混合声音，另外包含“手机原声”和“电脑人声”两条独立音轨，方便后期分别调音。播放器通常一次只播放所选音轨；剪辑软件可按轨导入。

同时保留 `phone-capture.mkv`、`phone-audio.wav`、`mac-microphone.wav`、降噪后的麦克风、`session.json` 和本次日志。只有电脑麦克风经过降噪；不按 ASR 提问片段裁切讲话，不对游戏和助手播报做人声降噪。降噪器本身的约 10ms 延迟会被补偿。

断连、源进程退出、文件缺失或合成失败会标记异常，已写入的原素材保留。临时成片通过尺寸、30fps、三音轨和解码检查后才会改为正式文件名。进程锁用于防止重复开录；脚本仅结束自己启动的采集进程，不退出游戏或听野，不使用 `killall`。

有原素材但合成中断时，可以离线重试：

```sh
python3 scripts/record_android_demo.py recover --directory output/video/某次录制目录
```

恢复文件另存为 `demo-recovered-30fps.mp4`。若原素材目录已删除，则无法用此命令恢复。活动状态存于成片目录之外，`status` 会明确显示 `sources_missing`。

麦克风与手机音轨目前根据文件创建时刻估算对齐，仍包含设备初始化与缓冲误差，尚未完成定量同步标定。`--mic-offset-ms` 可应用短录已校准的相对偏移（正值延后麦克风）；不要以默认估算作为精确同步保证。USB 和耳机解决的是无线链路与扬声器回录问题，实际整局表现仍需在这套连接下确认。

无线备用模式需显式加 `--allow-wireless`；没有声音监听需求时可用 `--no-monitor`，手机内部声音仍会保存。正式 Demo 优先采用上述 USB 与耳机配置。
