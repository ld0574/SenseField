# 听野：黑客松方案收敛与实施路线

更新日期：2026-09-30

状态：已定方案，待实施。本文合并了两轮独立的架构评审，没有启用新模型、修改运行参数或宣称用户验收通过。实际能力以 Android assets、代码和 `validation/STATUS.md` 为准。

## 1. 结论

现有的截屏 → ROI → ncnn → C++ 时序跟踪 → Java 提示调度底座继续使用。这一轮只做一件事：

> 小地图上已经显示的敌方英雄标记进入玩家自身标记附近时，提醒一次方位；持续存在不重复；证据不足时明确告知“雷达暂停”。玩家自己决定怎么操作。

这是待目标玩家验证的方向，不是“对所有低视力玩家有效”的结论。如果目标玩家最大的困难不在小地图，而在中央战斗画面、菜单或技能辨认，应根据反馈调整目标，不能用检测分数代替需求验证。

## 2. 已定决策

| 决策 | 内容 | 理由 |
| --- | --- | --- |
| 主画面血条分支 | 冻结，`main_red_bar=false`，代码和复核数据保留 | 血条粗细分不出英雄与小兵、野怪；镜头拖走后，屏幕边缘不等于玩家身边 |
| 坐标原点 | 小地图上的自身标记 | 小地图坐标与主镜头无关，敌我在同一张固定地图上 |
| P0 事件 | 只做一种：近区占用 | 多敌人、团战、换号都归入同一个占用时段，不拆成多种事件 |
| 冷却 | 新事件不叠加 15 秒全局冷却；用占用时段去重和 REARM 稳定窗口 | 全局冷却会压掉“敌人退走又回来”的第二次接近 |
| 方位 | 8 向扇区，带滞回 | MOBA 中斜向信息有用；滞回防止边界抖动 |
| 证据不足 | UNKNOWN 持续约 2 秒响一声低音，恢复时响一声柔和音 | 对看不清屏幕的人，静默听起来和“附近没人”一样 |
| 评估证据 | 冻结后录制新的授权对局作为主要证据；`video9`、`video12` 继续封存 | 新对局同时覆盖真机和目标玩家，也不破坏封存规则 |

## 3. 现状与缺口

已具备：

- 端侧链路在 Android 14 实体机跑通截屏、ncnn 和播放（`validation/ANDROID_LIVE_SMOKE_2026-09-29.md`）。
- 双类 v6 512 候选（`minimap_enemy` + `minimap_player`）在开发 val 上的 player P/R 约为 95.45% / 90.32%，中心误差 P95 约 6.29 px；val 参与了选模，test 为空，只是开发诊断（`validation/MINIMAP_PLAYER_ACTIVE_LEARNING.md`）。导出产物在本地忽略目录 `build/ignored/v6-512-export`。
- Android 已支持多类别 metadata、320–1024 输入和按类别 NMS；原生引擎已有自身单例轨迹和 500 ms 新鲜度约束；`CueArbiter → CueDispatcher → CuePlayer` 已有过期、去重、优先级和抢占。

缺口：

| 缺口 | 证据 | 处理 |
| --- | --- | --- |
| APK 仍是 320 单类敌方模型 | `android/app/src/main/assets/profile.json` 与 metadata | WP-B 接入双类实验 profile |
| 置信度二次过滤 | `events.min_confidence=0.67` 在 `ma_engine_step` 中对所有类别再过滤一次；v6 逐类阈值为 0.57/0.59 | 实验 profile 的 `events.min_confidence` 设为 0.57，逐类过滤只在 bridge 做一次；只换权重会悄悄丢掉 0.57～0.67 的检测 |
| 只在 APPEAR 时处理 | `CueArbiter` 只处理带 APPEAR 转换的敌方实体 | “远处出现、后来走近”不会提示；关系层必须每帧计算 |
| 去重键依赖 trackId | `CueEventKeys.visionMemory()` 拼接 trackId；trackId 由最近邻分配，交叉或重现时会换号 | 新事件按占用时段去重 |
| 提示没有方向 | `CueRouting.unlocatedMinimapEnemyDirection()` 恒为 0，文案固定 | 由关系层给出扇区 |
| 声像只有全左、全右 | `CuePlayer.playToneLocked()` 只处理 direction 1/2；`CueRequest` 没有连续声像字段 | 增加连续声像 |
| 日志解析器词表封闭 | `android_session_log.py` 的 `KIND_BY_CODE` 只认 1–5，并拒绝未知 kind、direction 和类别 | 新 kind、类别和日志行必须同步加入，否则新日志会被判为格式错误 |
| 新权重可能入库 | `.gitignore` 只忽略 320 单类 `.bin` | 新 `.bin` 文件名加入 `.gitignore`，提交前运行 `scripts/check_public_repo.py` |

## 4. P0 近区事件规格

### 4.1 坐标

- 自身点 P、敌方点 E 取已确认实体框的中心，坐标为整帧归一化值。
- 只使用 `VISIBLE` 且 `freshness_ms ≤ 500` 的实体。`LOST` 残影不参与计算。
- 自身点必须落在地图主体矩形内，否则进入 UNKNOWN。地图主体使用 profile 的 `minimap_direction`，不用带安全边距的检测 ROI，也不用 512 的模型输入尺寸。

```text
L  = min(minimap_direction.w * W, minimap_direction.h * H)   // 地图主体短边像素；当前开发机约 390 px
dx = (E.x - P.x) * W / L
dy = (E.y - P.y) * H / L
d  = hypot(dx, dy)                                           // 以地图短边为单位的相对距离
θ  = atan2(-dy, dx)                                          // 屏幕 y 向下，取负号使“上”为 90°
```

d 只表示小地图上的相对距离，不是米数、攻击范围或可通行距离。方位按小地图、以自身为中心，不是英雄朝向。只支持已标定的固定布局；实施前用截图确认 `minimap_direction` 确实框住地图主体。

### 4.2 状态机

```text
UNKNOWN  ：自身或地图不可靠。静默；持续超过阈值时响一声低音
CLEAR    ：可靠观察下，R_enter 内没有敌方。静默
PENDING  ：R_enter 内出现候选，等待多帧确认
OCCUPIED ：确认后提示一次；持续占用保持静默
REARM    ：所有敌方离开 R_exit（或不再可见）后，稳定满窗口才回到 CLEAR
```

规则：

1. 每帧更新关系，不依赖 APPEAR。“远处出现后走近”和“玩家主动走近”都要能触发。
2. 按占用时段去重，不按 trackId。同一时段内多个敌人进出、交叉换号，都只提示一次。
3. R_exit 大于 R_enter，防止在边界来回触发。
4. 不叠加 15 秒全局冷却，也不走 `CueArbiter` 现有的小地图 APPEAR 冷却路径和原生 `minimap_min_gap_ms`。频率由占用时段去重和 REARM 窗口控制。
5. OCCUPIED 期间自身短暂丢失（不超过短失效容忍时间）时保持状态，不清空、不重播。超过容忍时间进入 UNKNOWN；恢复后重新确认，若近区仍有敌方，作为新时段提示一次。
6. 暂停、旋转、断流恢复、原生 reset、新会话都清空状态，不补播旧事件。
7. 每个被抑制的候选都记录原因（如 `rearm_pending`、`short_gap`、`self_unknown`、`playback_failed`），用于核查漏报。

### 4.3 方位

- 8 个 45° 扇区：右、右上、上、左上、左、左下、下、右下。
- 滞回：扇区边界两侧各 7.5°；在 PENDING 期间保持上一扇区，确认时报当前扇区。
- 多个敌方时取最近的可靠目标。
- 以下情况只提示“附近有敌人”，不报方向：最近目标 d < 0.2 × R_enter（贴身），或最近两个目标距离相差不到 10% 且扇区不同。

### 4.4 参数初值

集中写在 profile 的新 `minimap_relation` 段，默认关闭。下表是起点，试玩后冻结，不是通用常数。

| 参数 | 初值 | 说明 |
| --- | --- | --- |
| R_enter | 标定得到（暂定 0.20） | 挑约 20 帧“敌方英雄刚进入主画面边缘”的截图，取其小地图 d 的中位数；工具 `python -m mapassist.calibrate_near_zone` |
| R_exit | 1.25 × R_enter | 滞回 |
| 确认 | 最近 3 帧中 2 帧在近区 | 与现有 2/3 确认一致 |
| REARM 窗口 | 3000 ms | 可靠观察下持续无近区敌方；太吵就加长 |
| 短失效容忍 | 2000 ms | 同时也是 UNKNOWN 低音的触发时长 |
| 低音最小间隔 | 10000 ms | 防止手指遮挡等造成反复响 |
| 新鲜度 | ≤ 500 ms | 沿用 `MA_PLAYER_RELEVANCE_MAX_AGE_MS` |
| 优先级 / 有效期 | 80 / 1200 ms | 沿用端侧方案为“可靠危险接近”预留的档位 |
| 语音去重窗口 | 1000 ms | 只防同帧重复，不承担冷却 |

### 4.5 输出

| 事件 | 标准预设 | 详细预设 |
| --- | --- | --- |
| 近区占用 | 声像短音 + “左上，敌人”；不报方向时说“附近有敌人” | 同标准 |
| 雷达暂停 / 恢复 | 低音 / 柔和音，不用语音 | 同标准（语音会触发类别冷却，可能吞掉复活后紧接着的近区短语） |
| 远处新敌人（现有 APPEAR 中性音） | 双类 profile 下关闭 | 可选开启 |
| 震动 | 近区默认关闭；可开为单次无方向脉冲 | 同标准 |
| 视觉层 | 默认关闭 | 可选；给观众演示用 |

- 精简预设：近区只用声像短音，不说话。
- 声像：`pan = cos θ`，右为 +1、左为 −1、正上正下居中；上下由语音表达。
- 新提示音与现有 5 种可区分，低音频率避开死亡音（360 Hz）。
- 新手引导用长句解释一次：“方位按小地图、以你自己为中心；‘左上，敌人’表示有敌方标记进入你左上方附近”。
- 文案只陈述事实，不说“危险”“有人来抓你”“安全”。
- 新类别命名为 `NEAR_ZONE`，单独开关，不复用默认关闭的 `DANGER`。

### 4.6 日志

- `NearZoneState`：状态变化、原因、时间戳；用于计算证据覆盖率。
- `NearZoneEvent`：每个时段的提示或抑制，含 episode、扇区、pan、d 和抑制原因。
- `CueEvent` 新 kind：7 = `near_zone`，8 = `radar_status`，在 `mapassist.h` 统一定义，日志解析器同步加入。

## 5. 工作包

WP-A 与 WP-B 并行；WP-C 依赖 WP-B 的双类实体输出；WP-D 依赖 WP-C。每个包单独可用、可回退。

### WP-A 需求与话术验证（10/1–10/2）

- 导师日先问目标玩家：现在玩的时候最大的困难是什么？小地图是不是最痛的点？听到“左上，敌人”之后能做什么？
- “人肉雷达”试验：目标玩家正常打一局人机；队友在征得同意后投屏看小地图，敌方进入大约一屏范围时按固定话术喊“{方位}，敌人”，持续存在不重复喊。
- 记录：8 个方位词是否听得明白、能否据此行动、多少次开始觉得烦、团战要不要安静、喜欢短音还是语音、是否使用耳机或骨传导。
- 人工喊话比系统慢，只验证话术和频率，不代表系统时延；公开材料标明是人工原型。

完成标准：定下 P0 话术、通道和可接受的频率。若小地图不是最痛的点，10/2 前调整目标。

### WP-B 双类实验模型上机（10/1–10/3）

- 把 `build/ignored/v6-512-export` 的 ncnn param/bin 以新名字放入 `android/app/src/main/assets/`，新增 metadata：`classes=[minimap_enemy, minimap_player]`、`input=[1,3,512,512]`、`output=[1,5376,7]`、`postprocess.confidence_by_class={minimap_enemy:0.57, minimap_player:0.59}`、param/bin SHA-256、`release_ready=false`。
- `.gitignore` 加入新 `.bin` 文件名；权重不入库，提交前运行 `scripts/check_public_repo.py`。
- 新增实验 profile：绑定新 metadata，`minimap_yolox_input_size=512`，`events.min_confidence=0.57`，`verified=false`。保留 320 单类 profile 作为回退；试玩构建默认使用双类实验 profile，设置中可切回单类。
- 真机测量：处理耗时 P50/P95、有效帧率、敌我同时可用的比例，以及粗测温度和游戏帧率。
- 一致性抽查：在同一台手机上全屏播放它自己录的对局，让 app 截屏识别，与桌面 `training/replay_yolox_ncnn.py` 对同一段录像的结果比较。

完成标准：日志证明手机加载的是双类权重，类别、坐标和时间一致，耗时有实测数据。若 P95 明显拖慢事件，退回 v5 416 或缩小输入重训，不用放宽阈值冒充达标。

### WP-C 近区关系层（10/3–10/8）

原生（Android 与离线回放共用，避免 Java、Python 各写一套规则）：

- 新增 `native/src/minimap_relation.cpp`，加入 `native/CMakeLists.txt` 的 `mapassist` 库；Android 通过 `add_subdirectory` 自动带上。
- `native/include/mapassist.h` 追加关系层 API，`MA_API_VERSION` 升到 9。大致形态：`ma_relation_create(config)`、`destroy`、`reset`，以及每帧在 `ma_engine_step` 之后调用的 `ma_relation_update(relation, entities, count, minimap_direction, width, height, now_ms, out)`。
- 输出包含状态、转换、扇区（0 = 无方向，1–8）、pan、最近 d、episode id 和抑制原因。不借用 `MA_MAIN_ENEMY`，不改 APPEAR 的含义。

JNI 与 Java：

- `native_bridge.cpp` 每帧调用关系层，把结果写进 `NativeFrameResult` 的 version 2 packet；解析器继续兼容 version 1。
- 关系层参数用单独的配置调用传入，不再扩大 `nativeCreate` 的参数列表；`GameProfile` 解析 `minimap_relation` 段。
- `CueRequest` 增加 pan；`CuePlayer` 支持连续声像和新提示音。
- `CueRequest.Category` 增加 `NEAR_ZONE`；`CueSettings` 增加开关、预设通道和去重窗口；`AlertSettingsActivity` 增加“附近敌人提醒”开关。
- `CueEventKeys` 增加 `nearZone(resetGeneration, episodeId)`。
- `CaptureService` 把关系层转换路由给 `CueDispatcher`，不经过 `CueArbiter` 的小地图冷却路径；写 `NearZoneState`、`NearZoneEvent` 日志。

Python：

- `python/mapassist/native.py` 增加关系层 ctypes 绑定；`training/replay_yolox_ncnn.py` 输出逐帧近区状态和事件。
- `python/mapassist/android_session_log.py` 加入 kind 7、8，`NEAR_ZONE` 类别和新日志行，并能统计覆盖率和抑制原因。

完成标准：第 6 节合成用例写成 native CTest，Python 侧用 ctypes 复跑关键用例；`pytest`、`:app:testDebugUnitTest`、`:app:assembleDebug`、`:app:lintDebug` 全部通过；离线回放能给出开发录像的每分钟提示数和覆盖率。

### WP-D 试玩、冻结与证据（10/7–10/14）

- 10/7–10/8：目标玩家第一次上手，反馈带去导师日 ②。
- 10/9–10/12：按反馈迭代，10/12 前冻结模型、阈值和规则；同步修正 `docs/技术方案.md` 第 12 节和 `docs/视野记忆.md` 中已经不符合实现的描述。
- 10/13–10/14：冻结后录制新的授权对局。完整会话要正常结束并有 `SessionSummary`。逐条复核发出的提示得到 precision；抽查“应提示未提示”的时段估计 recall；用外部录像测约 20 个事件的“画面到发声”延迟；开、关雷达的顺序交替。

完成标准：有可复查的事件记录和目标玩家反馈。只做到离线回放时，如实说明，不声称实机辅助已验收。

## 6. 合成回归用例

| 场景 | 期望 |
| --- | --- |
| 敌方在远处出现，后来走近，中途没有新 APPEAR | 进入近区时提示一次 |
| 玩家主动走近已显示的敌方 | 提示一次 |
| 在 R_enter 与 R_exit 之间来回抖动 | 只提示一次 |
| 持续占用 30 秒 | 不重复 |
| 同一时段内多个敌方进出、交叉换号 | 只提示一次 |
| 离开超过 REARM 窗口后再进入 | 再提示一次（不受 15 秒限制） |
| 离开未满 REARM 窗口就回来 | 不提示，记录 `rearm_pending` |
| 自身丢失 < 2 s | 不清空，不重播 |
| 自身丢失 ≥ 2 s | 一声低音；恢复时一声柔和音，重新确认 |
| 手指遮挡使状态反复抖动 | 低音至少间隔 10 s |
| 只有 LOST 残影的敌方 | 不参与近区计算 |
| 自身点落在地图主体外 | UNKNOWN |
| 扇区边界 ±7.5° 内抖动 | 扇区不跳 |
| 贴身，或两个距离相近、扇区不同的目标 | 不报方向 |
| 暂停、旋转、断流、reset | 清空状态，不补播 |
| 播放失败或过期 | 记录原因，不排队重播 |

强制负场景（用录像抽查）：展开大地图、阵亡与观战、回放、菜单与结算、按住小地图拖动镜头。

## 7. 评估指标

| 指标 | 定义 | 初始目标 |
| --- | --- | --- |
| 证据覆盖率 | 活跃时间中处于 CLEAR、PENDING、OCCUPIED 或 REARM 的比例 | 如实报告 |
| 近区提示 precision | 符合定义的提示 / 全部发出的提示 | 如实报告 |
| 近区提示 recall | 应提示时段中成功提示的比例；漏报按漏检、自身未知、REARM 抑制、播放失败分开统计 | 如实报告 |
| 打扰 | 每分钟错误或无关提示数 | < 1 |
| 延迟 | 条件首次在画面上成立到实际发声的 P50 / P95 | P95 ≤ 500 ms |
| 玩家 | 是否听懂、是否打断操作或交流、是否愿意下一局继续开 | 引用原话需授权 |

覆盖率必须和误报一起报告：一直静默也能让误报很低。500 ms 是开发目标，原有 250 ms 发布门禁不变；这些目标都可以和目标玩家再协商。

## 9. 现场演示

1. 目标玩家授权截屏，确认提示含义，选择通道。
2. 远处有敌方标记：静默。
3. 敌方进入近区：从对应方向传来短音和“左上，敌人”；持续存在不重播。
4. 敌方离开后，超过 REARM 窗口再回来：再提示一次。
5. 按住小地图或自身定位失效：一声低音，不说“安全”；恢复时一声柔和音。
6. 一键暂停，提示停止；展示实际日志和失败案例。

给评委看“雷达看到了什么”时，用回放画面或调试 overlay，和目标玩家听到的声音分开展示。功能完成前，只展示现有链路或标明是人工原型。

## 10. 本轮不做

- 全量清洗 901 张玩家标注：只针对失败场景定向补样本。
- 逐人提醒、人数播报、接近速度、随时语音查询：留作 P1，由试玩反馈决定。
- 为提高召回而降低检测阈值，或修改 `verified`、`release_ready` 标记。

主画面分支重启的前提：近区提示已证明有用，目标玩家仍明确需要屏幕边缘信息，团队有验证能力。届时优先试“小地图把关”：雷达显示某一侧有敌方靠近时，才去主画面那一侧找血条。重新标注使用 `enemy_hero_bar / non_hero_red_bar / ui_or_effect / uncertain`；现有红色候选只能作候选和困难负样本，不能直接转成英雄标签。
