# 识别错误根因分析与修复方案（真机第一关 7×7 案例）

> 触发：真机进入开心消消乐第 3 关，第一步识别播报即错误。附真机截图两张（7×7 棋盘）。

## 一、根因分析（按置信度排序）

1. **棋盘规格错位（首要根因，确定性高）**：真机该关棋盘为 **7 列 × 7 行**，而识别器默认 **8×8** 切格。8 条网格线压在 7 列棋子上，每格采样到相邻两颗棋子的混合色——全盘无一格正确。开心消消乐的棋盘规格随关卡变化（6×6 到 9×9 都有），固定 8×8 必然在部分关卡全错。
2. **调色板错配（次要）**：该关只有 4 种动物（棕熊/小鸡/青蛙/蓝河马），无狐狸/紫猫；六色 HSV 桶会把「棕熊的暗橙」硬猜成 O、把高光猜错。
3. **立体造型**：动物棋子有高光/阴影/描边，非纯色块；中心 16×16 平均色会被高光拉偏。

## 二、修复方案（三层，按优先级）

### 修复 1（立即）：行列快速适配
辅助页标定卡已有行数/列数拨盘（6–9），**进新关卡先数格子设对行列再采样**。下一版把「行/列」拨盘提升到采样按钮旁边并加「本关 7×7 / 8×8」快捷记忆（按关卡记住规格）。

### 修复 2（下一版核心）：行列自动检测
在 autoDetectBoard（深色区域包围盒）基础上，检测盒内**暗色格线周期**：对包围盒逐行/列统计暗像素占比的周期性峰谷，推算行列数——自动输出「7×7」而不是猜。失败回落手动拨盘。

### 修复 3（云端 VLM 兜底，本方案核心新增）：把棋盘截图交给视觉大模型
颜色规则对立体卡通棋子天然脆弱；VLM（视觉语言模型）直接「看图报矩阵」，对任意美术风格通用。渠道与模型（领导指定三选，均已具备）：

| 模型 | OpenRouter 调用 | 特点 |
|---|---|---|
| Qwen3-VL（通义千问视觉） | `qwen/qwen3-vl-...` | 性价比高，中文场景强 |
| GLM-4.5V／GLM-5.3V（智谱） | `z-ai/glm-4.5v` 等 | 国内直连快 |
| DeepSeek（文字推理强） | 文本-only，做矩阵校验与策略判断，不做看图 | 与 VLM 组合用 |

调用协议（OpenRouter chat completions，已有 API Key）：
- 请求：board 区域裁剪图（base64）＋ 固定提示词：「这是三消游戏棋盘，输出 JSON：{"rows":N,"cols":M,"grid":[["颜色名",...],...]}，颜色限定 红狐狸/小鸡/青蛙/河马/棕熊/紫猫/未知，按行列顺序，禁止额外文字」
- 响应解析 → Match3Board 检测 → 播报（复用现有链路）
- 门控：响应不含合法 JSON 或行列与标注不符 → 降级「没看清」话术
- 成本：单次约 1000–2000 token，价格模型约 ¥0.01/次以内

### 触发策略（自动云端调用）
颜色采样结果「未知格占比 >25%」或「连续两次采样矩阵互相矛盾」→ 自动升级云端 VLM 识别一次；成功则缓存为该关参考。用户也可手动点「云端视觉识别」按钮。

## 三、与 Jev 判断式架构的关系

VLM 解决「看」（L1 感知），Jev 解决「判」（L2 决策）——正交组合：
- 看棋盘：颜色采样（快、免费、离线）失败 → 云端 VLM（准、慢、花钱）
- 做决策：屏幕类型/弹窗/敏感闸门等判断 → Jev 判断式（本地 Laya 或云端）
- 低置信升级：Jev ABSTAIN → 云端大模型（DeepSeek 文本推理）
