# 手机屏幕无障碍识别：判断式（Jev 风格）改造方案（领导提供，作为规格）

> 思路来源：Datawhale《Jev 中文教程》。传统 LLM「生成文本→解析回决策」慢、贵、易碎；Jev 只做判断不写文本：输入「状态+类型化问题」，直接返回带概率与置信度的结构化答案（Choice/Score/Noul），骨架是扇出/门控/路由。

## 一、为什么适合屏幕无障碍

| 痛点 | 判断式解法 |
|---|---|
| 播报要实时，VLM 生成再解析延迟扛不住 | 只输出结构化字段，无长文本生成 |
| 屏幕含密码/验证码/金额，不敢上云 | 小参数判断模型可端侧离线 |
| 读错比没读到危害大 | 每答案自带置信度，可门控与拒答降级 |
| 下游驱动 TalkBack/焦点/手势 | 输出即结构化决策，无需脆弱解析 |
| 图标/无标签控件语义歧义 | Choice 固定候选集，把歧义关进候选里 |

改造原则：把「请描述这个屏幕」换成「请回答这个屏幕的 N 个是非/选择/打分问题」。

## 二、子任务→原语映射（P0 先做 1，逐步扇出 2/3，其余按需）

| 子任务 | 原语 | 输出 |
|---|---|---|
| 1. 屏幕类型识别（列表/表单/支付/弹窗/验证码/加载中…） | Choice | 类别+概率+置信度 |
| 2. 模态弹窗遮挡判定 | Noul | 0-1 |
| 3. 敏感信息识别（密码/验证码/金额/隐私） | Noul | 0-1，≥0.6 触发保护 |
| 4. 无文字图标语义消歧 | Choice（固定候选） | 语义+概率 |
| 5. 播报优先级排序 | Score | 分数+概率 |
| 6. 操作结果确认（成功/失败/无变化/弹窗拦截） | Choice | 类别+概率 |
| 7. 可点击/可聚焦判定 | Noul | 0-1 |

## 三、门控（置信度分层，宁可少说不错说）

- ≥0.85 直接播报（语气确定）
- 0.60-0.85 播报+降级话术（「可能是…」）
- <0.60 拒答（「这一屏我没看清楚，要我从上往下逐条读吗？」）
- 高风险（金额/删除/支付/授权）阈值 0.95＋强制二次确认

## 四、状态构造（胜负手）

1. 以无障碍树为主、视觉为辅；冲突时可操作性以树为准，语义以视觉补
2. 树必须压缩：只留 可见+可聚焦/可点击/有文本 的节点；去掉容器空壳；按分区（顶栏/主内容/底栏/浮层）分组；节点短 ID（n1,n2…）
3. 上下文：前台包名/页面名、上一屏类型、用户刚做的操作、当前目标（语音指令）、深色模式/字体倍数/横竖屏

## 五、全局系统提示词要点（对应 SystemOne instructions）

证据优先（引用节点 ID）；不确定就低置信度；涉敏默认降一档并 needConfirm；树与视觉冲突标注 conflict；不使用屏幕外假设。

## 六、降级与拒答话术

- 0.60-0.85：「{内容}，这个我不太确定。」
- <0.60：「这一屏我没看清楚，要我从上往下一条条读吗？」
- 高风险+needConfirm：「接下来是 {操作}，{关键内容}，确认吗？」
- 敏感命中：「这里像是有 {类型}，要我读出来吗？」
- 加载中：「页面还在加载，好了我叫你。」

## 七、落地坑

1. 判断（结构化高频低延迟）与描述（自然语言播报）分开，判断结果作为描述的硬约束
2. 阈值按场景分层（支付/删除 0.95＋二次确认）
3. 状态压缩比模型选型更影响效果
4. confidence 先校准再用（真实屏幕数据分箱校准）
5. Laya vs Jev 官方自评缺第三方复现，必须用自有数据实测
6. 端侧优先（隐私）；云端仅在不涉敏且用户明确授权时
7. 先做基线（单个屏幕类型 Choice）再逐步扇出
