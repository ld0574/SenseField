# ADR-0001：Jev 渠道选型与「可替换后端」架构决策

- **状态**：已接受（Accepted）
- **日期**：2026-10-02
- **决策人**：项目组
- **影响范围**：听野无障碍游戏辅助工具 · L2 判断层
- **相关文件**：`无障碍判定创作工具.html`、`samples/*.json`、`PROGRESS.md`、`BLOCKED.md`

---

## 1. 背景（Context）

本项目在 L2 判断层使用 TypeSafe AI 的 Jev（System One 模型），把「屏幕 → 文本 state」之后的语义判断交给它，返回 `choice` / `score` / `noul` 三类类型化答案，再由 L3 Harness 授权与执行。

落地时需要回答一个问题：**能否长期在腾讯云 EdgeOne Makers 控制台上调用 Jev 做开发与测试？**

调研后确认了三条此前被误判的事实：

### 1.1 不存在「阿里的 Jev」这回事

| 角色 | 归属 | 与 Jev 的关系 |
|---|---|---|
| TypeSafe AI | 美国旧金山独立初创公司（2024 年成立，创始人 Diogo Almeida 等；2026-09-15 发布 Jev，4000 万美元种子轮由 DCVC 领投） | **技术来源 / 模型提供方** |
| Qoder（阿里云） | 阿里云智能体编程平台 | **下游集成方之一**：把 Jev 接入自身 Agent Harness，用于 Auto Mode 权限判定与浏览器动作选择 |
| EdgeOne Makers（腾讯云） | 腾讯 | **另一个下游渠道**：2026-09 上架内置模型 `@makers/jev`，无需自管 TypeSafe 账号与密钥 |

**结论**：阿里与腾讯在此处是**并列的渠道方**，均为 TypeSafe 的客户，不存在「阿里技术跑在腾讯控制台上」的依赖关系。Qoder 那篇实践文章对本项目的价值是**架构范式参考**（「Jev 判断，Harness 授权与执行」的职责切分），不是技术依赖。因此「腾讯系控制台 + 阿里系技术」的阵营顾虑**不成立**。

### 1.2 真正的风险在 TypeSafe AI 自身

| 编号 | 风险 | 证据 |
|---|---|---|
| R1 | **无公开权重、无法自托管** | 官方模型没有公开权重与离线构建，不可自部署；服务部署在美国西海岸 |
| R2 | **速率限制动态调整** | 官方文档直言 limits "are adjusting dynamically"，可能无通知变更；上线初期曾因需求超载一度无法对外服务 |
| R3 | **免费额度是限时的** | Jev 在 Vercel AI 网关的免费期已于 2026-09-25 结束；EdgeOne 侧标注同为「限时免费」，属渠道获客补贴而非长期承诺 |
| R4 | **额度与实时游戏循环的用量不匹配**（见 §2） | 控制台实测额度 500,000 Token / 30 天 |
| R5 | **数据出境合规** | state 含屏幕内容 + 用户视力状况 profile，属敏感个人信息 |
| R6 | **公司处于融资早期** | 种子轮后正在洽谈 10 亿美元级新融资，估值与产品形态尚未稳定 |

### 1.3 一条反直觉但对项目有利的判断

业内已有公开质疑（模型评测平台 Arena CEO）：**看不出 Jev 与标准的零样本分类器有何区别**，该类技术已相对成熟。

如果这一质疑成立，对本项目的含义是：**真正的资产不在 Jev 这个模型，而在本项目的 state schema 与原子问题设计**。前者会被替换，后者沉淀在我们自己手里。

## 2. 额度测算（R4 量化）

**依据**：官方示例「一条短工单文本 + 3 个问题」= **392 input token**。本项目 8×8 棋盘 + 五问的 state 更大，且中文 instructions 的 token 化成本高于英文。

**估算**（保守区间）：

| 项 | 取值 |
|---|---|
| 单次请求 input token | 600 – 900（取 800 计算） |
| 月度额度 | 500,000 Token / 30 天 |
| **月度可用请求数** | **约 550 – 830 次** |
| **折合每日** | **约 18 – 28 次** |

**判定**：一次消消乐真实对局的决策点远不止 28 次。
**结论**：免费额度**不足以支撑开发期的高频游戏循环测试**，仅够功能验证与少量真机试跑。必须尽早规划付费或本地兜底。

---

## 3. 决策（Decision）

### D1：验证期继续用 EdgeOne，但不绑定

EdgeOne Makers 是当前最省事的渠道（国内边缘节点、无需自管 TypeSafe 账号与密钥、延迟低）。**本期继续用它做功能验证**。

### D2：采纳「可替换后端」架构——把 Jev 从依赖降级为一个实现

`/v1/systemone` + `choice` / `score` / `noul` 这套请求形状已成为事实标准，开源社区已产出**协议兼容的复刻实现**（Apache 2.0 等宽松协议）：

- **Laya**：判别式架构（ModernBERT / mmBERT 骨干），约 322M–421M 参数；内置英文与多语言双分支自动路由，**中文场景有专门权重**；单次前向 p50 约 8–16 ms；锁定单分支显存约 1.25 GB
- **OpenJev**：Docker + vLLM 起服务，直接暴露**与 Jev 兼容的 HTTP API**，客户端改地址即可切换
- 另有 NanoJev、APUS-OpenJev(GGUF)、Kev 等独立实现

**因此**：把全部调用收敛到单一接口 `JudgmentClient.judge(state, questions) → answers`，其下挂三个可互换实现：

```
JudgmentClient（接口）
├── EdgeOneJevClient      # 现网渠道，默认
├── OpenRouterJevClient   # 备选，无需排队
└── LocalSystemOneClient  # Laya / OpenJev 自托管，兜底
```

**硬性约束**：endpoint 与 model 字符串只允许出现在各 Client 实现内部，业务代码与 Harness 中**不得散落**任何 endpoint / model 字面量。

### D3：本地兜底不是备胎，是本产品的刚需

- **合规**：视障用户的屏幕内容 + 视力 profile 属敏感个人信息，能不出境就不出境
- **可用性**：断网时游戏不能变砖，毫秒级本地推理比任何云端都稳

### D4：合规前置

产品面向真实视障用户发售前，state 出境事项必须先行与法务对齐，**不得拖到上线前**。

## 4. 备选方案与被否决理由

| 方案 | 否决理由 |
|---|---|
| 直接申请 TypeSafe 官方账号 | 早期访问属性、限流动态调整、服务在美西、需自行管理密钥；对国内团队不最优 |
| 只走 OpenRouter | 同样依赖 TypeSafe 供给，不解决 R1/R2/R5；仅作备选渠道 |
| 完全自建分类模型（不复用 System One 协议） | 重复造轮子，且丧失协议带来的可替换性；与 D2 冲突 |
| 直接放弃 Jev，改用通用 LLM 出 JSON | 丧失延迟与成本优势，且重蹈「解析生成文本」的覆辙，与选型初衷相悖 |

---

## 5. 后果（Consequences）

**正面**
- 渠道切换成本趋近于零，R1/R2/R3 的供应商风险被结构性化解
- 本地部署同时解决 R5 合规与断网可用性
- 评测集与原子问题设计沉淀为自有资产

**负面 / 需付出的代价**
- 需要维护一层适配代码与契约测试（一次性投入，约 1–2 天）
- 本地实现准确率低于云端 Jev，需重新标定置信度阈值，**不能照搬现有阈值**
- 多一条部署链路（服务端容器或本地进程）需要运维

**中性**
- 需持续跟踪 TypeSafe 与开源复刻两边的进展，建议每季度复审一次

---

## 6. 迁移触发条件（Triggers）

任一条件满足即启动对应动作，不靠感觉判断：

| 编号 | 触发条件（可观测、可判定） | 动作 |
|---|---|---|
| **T1 额度** | 月度用量 > 60% 且剩余天数 > 10 天 | 启动本地双跑评测，准备切量 |
| **T2 准确率** | 同一标注集上，本地实现与 EdgeOne 的 top-1 一致率 ≥ 90%，且低置信率差 ≤ 10 个百分点 | 允许将非关键判定切至本地 |
| **T3 合规** | 产品进入面向真实用户的测试阶段 | 敏感 state 一律走境内 / 本地，云端仅处理脱敏数据 |
| **T4 可用性** | 连续 2 次网络失败，或 P95 延迟 > 800 ms | 本地兜底自动接管，云端降级为可选 |
| **T5 供给** | TypeSafe 官方限流或定价发生对本项目不利的变更 | 评估全面切本地 |

---

## 7. 复审

- **复审周期**：每季度一次，或 T1–T5 任一触发时立即复审
- **复审要点**：额度消耗曲线、本地与云端准确率差值、开源复刻实现的新版本、TypeSafe 融资与产品形态变化、数据合规要求变化

---

## 8. 待办（由本 ADR 派生）

1. 抽出 `JudgmentClient` 接口，收敛全部 endpoint / model 字面量
2. 建 50–100 帧带人工标注的评测集（正确操作 / 正确播报）
3. 真 key 跑通后，在同一评测集上双跑 EdgeOne 与本地实现，记录准确率、P95、低置信率三项差值
4. 按实测分布重新标定本地实现的置信度三档阈值
5. 与法务对齐 state 出境口径
