## 一、阶段一：判定式骨架补全（目标：所有 Choice 带 ABSTAIN、闸门上线）

1. **ABSTAIN 全面化**：JevQuestion 的 Choice criteria 一律追加「ABSTAIN：信息不足以判断」；解析层收到 ABSTAIN 一律走低置信话术，即使 confidence 很高。【接入点：Match3AssistActivity.judgeScreen 的 questions 构造＋JevAnswer 处理】【验收：契约测试新增 ABSTAIN 用例】
2. **状态扩展**：SenseFieldReaderService 节点行补 enabled/checked/selected；状态头补 app/activity/时间/是否深色模式。【验收：状态字符串单测断言字段存在】
3. **敏感信息 Noul 闸门**（上云前先过）：判定请求前对 state 跑敏感 Noul（密码/验证码/身份证/银行卡/金额/隐私六类）；≥0.6 → 禁止该 state 上云（改用本地通道或直接播报「当前为 XX 页面，建议手动处理」）＋ needConfirm。【接入点：judgeScreen 与实时服务共用前置闸门】【验收：含模拟敏感树的契约测试，断言不上云】
4. **门控配置化**：阈值（0.85/0.60/0.95 高风险）从硬编码移入 routing-policy.json，按问题分级。【验收：改配置不改代码生效】

## 二、阶段二：扇出与路由（判定层完整形态）

1. **图标语义消歧 Choice**：候选集固定（返回/关闭/更多/搜索/分享/设置/消息/筛选/无法判断/ABSTAIN）；无 contentDescription 的图形默认装饰性，除非位置与上下文支撑。【验收：标注 20 个真实图标用例，准确率报告】
2. **播报优先级 Score**：候选节点按相关性/紧迫性/风险/显著度/冗余惩罚打分，降序播报，分数差 <2 合并，<3 不播。【验收：构造 10 节点场景，断言播报顺序】
3. **操作结果确认 Choice**：操作前后两次树状态＋expected → 按预期成功/失败/无变化/弹窗拦截/无法判断；「其余情况先播报现状，绝不自动重试」。【验收：模拟导航前后状态用例】
4. **低置信升级路由**：`r=决策模型(state,q)`；ABSTAIN 或 conf<0.5 → 脱敏后升级云端大模型（要求同样只返回枚举＋ABSTAIN）；0.5–0.8 → 播报候选等确认；≥0.8 直接执行。【接入点：新增 JudgmentRouter 类包住 JevClient】【验收：路由单测三档全断言】

## 三、阶段三：端侧化（国产开源模型上机）

1. **首选 Intern-Decision 0.8B/2B 多模态**（能看图/看界面再决策；官方称推理比 Jev 快 2–3 倍——须自测，见阶段四）；备选 Laya ONNX（已验证 PC 路线，纯文本判断）。
2. **上机档位**：2B/4B＋Q4 量化（参考 StartLux 4B≈2.71GB、一致率 98.3% 的先例），常驻内存预算 ≤1.5GB；27B 档不上机。
3. **端侧接口**：与 Laya 适配器同构——本地 HTTP/JNI 暴露 SystemOne 形状，LocalSystemOneClient 直接可用，手机离线时判定不出端。
4. **隐私硬规则**：敏感闸门命中的屏幕，端侧处理；云端只见脱敏文本意图。【验收：断言闸门命中时无云端请求】

## 四、阶段四：评测与校准（别把榜单写进方案）

1. **分层评测集**：按 App 类别（系统设置/社交通讯/支付金融/短视频/游戏）各建 ≥200 条「截图＋无障碍树＋标注」；报告分分层准确率，不看综合分。
2. **置信度校准**：真实数据分箱（Platt/等距分箱）后再定阈值；原始 confidence 默认过自信。
3. **阈值定案流程**：校准曲线 → 按操作风险分层（播报类低门槛/不可逆类 0.95＋二次确认）→ 写入 routing-policy.json。
4. 榜单数据（StartLux 31/38 高于 Jev 等）只作选型线索，一律以自建评测为准。

## 五、阶段顺序与依赖

阶段一（纯软件，1–2 天）→ 阶段二（2–3 天）→ **读屏判定真机验证（与阶段二并行，当前最大风险项：模拟器事件投递未通）** → 阶段三（依赖拿到真机与模型档位决策）→ 阶段四（持续，随阶段二起积累数据）。

## 六、需要领导拍板

1. Intern-Decision vs Laya ONNX 的端侧选型（影响包体积与是否多模态）；
2. 敏感闸门命中后：完全静默 vs 播报类型标签（文档建议后者）；
3. 分层评测集的数据采集授权方式（用户自愿上传脱敏树 vs 全端侧自采）。
