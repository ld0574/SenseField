# 开心消消乐：先服务任务，再考虑消除数量

根据听野的[公开规则引擎说明](https://github.com/ld0574/SenseField/blob/main/docs/development/match3-rules.md)、[元素参考](https://github.com/ld0574/SenseField/blob/main/docs/research/开心消消乐元素规则参考.md)整理。工程实现对待核实条目的限制优先于早期参考中的概述；单张图能认出身份，不代表能确认全部机制。

## 从问题到一步建议

1. 尽可能确认顶部剩余任务、是否完成、剩余步数，以及用户要解决的目标。看不清数值就保留未知，不猜关卡。
2. 区分普通动物、特效、覆盖层、不能移动的障碍和棋盘外空洞；重点确认候选交换涉及的局部区域，无需为问一条走法强行抄录整个棋盘。
3. 比较合法候选对剩余任务的确定贡献。能结束关卡优先；否则比较实际推进目标、解开通道和保留有效特效机会。已经完成的任务不继续加收益，最后一步不奖励“以后也许能用”的准备。
4. 只给一个有依据的动作及其与目标的关系。随机补子、后续连锁和不明机关不能说成保证发生；目标不明时可以说明哪个动作有确定消除，但不能称为全局最优。

## 高价值棋子不能被普通三消挤掉

看到魔力鸟时必须比较相邻可交换动物及其与剩余目标的关系。魔力鸟与普通动物交换会清除该颜色动物；双魔力鸟相邻互换可清屏动物。颜色数量最多不一定过关收益最高，应看这个颜色能否命中目标所在位置、解除覆盖或打通收集通道。

魔力鸟与直线特效的组合有大范围作用，要纳入比较；只有颜色、条纹方向和受影响区域能确认时才解释能覆盖哪些目标。不要编造全部随机横纵方向、连锁数量或“必过”。与爆炸等未完整核实组合不要给精确清除范围。

例如只剩右侧一个目标时，要先找能命中它的合法交换或特效用途，不能因为左上方能普通三消就一直推荐左上方。同样不能为了“用掉鸟”而浪费鸟；鸟的价值来自实际任务收益。

## 关键机制边界

| 可见状态 | 可以据此判断 | 不能直接推出 |
| --- | --- | --- |
| 普通动物 | 相邻交换后横／竖同色三连可消除；四连、直线五连、L／T 五格产生不同特效 | 颜色相近、发光都不足以确认特效；未见的补子不用于保证连锁 |
| 带横／纵条纹的直线动物 | 已确认方向的特效可影响整行／列，候选需结合实际触发条件 | 不确定条纹方向时不能声称能打到远处目标，也不能把所有特效都当成能任意点击激活 |
| 透明冰包裹动物 | 与静止冰面分开；包裹冻结状态禁止移动和配对，邻接消除可削层 | 不能推荐拖动被冻结动物，也不能只凭透明边缘确定层数 |
| 动物下面的已确认单层静止冰面 | 上面的动物可移动、可配对，消除上方动物可清冰面 | 不能把所有看起来像冰的格子都按这条处理 |
| 锁链／藤蔓缠绕 | 被锁动物不能移动，但可参与同色配对；按已确认邻接规则解锁 | 不能把它当成可交换的起点或终点 |
| 灰毛球 | 上下左右邻接消除可清；未清除的毛球走步后会跳动 | 不猜被遮住动物的颜色，不推定下一步跳到哪里 |
| 毒液 | 邻接消除可清除，可能扩散并与瓶子充能有关 | 不把毒液无条件排在任务完成之前，不猜扩散数量、方向和充能数 |
| 饼干等多格目标 | 比较周围合法消除和特效的任务机会 | 一个多格目标不是多个独立任务；命中一次不一定完成 |
| 蜂蜜覆盖／蜜罐 | 分别判断身份及邻接机会 | 不借用冰层的受击次数，不凭外观保证还需几次 |
| 金豆荚／钥匙等下落收集物 | 需要到达已确认的收集口，围绕通道考虑 | 离出口近不等于送达，有传送时不默认一直竖直下落 |
| 星星瓶／染色宝宝 | 能量和配对条件都确认后再讨论组合 | 发光不等于双方满能量，不明瓶子不套用星星瓶规则 |
| 花团、炮台、魔法石和新元素 | 描述身份和已确认作用，结合教程或用户说明 | 不从名字编造射程、层数、触发次数和全套新机制 |

小鸡图标可能是普通消除，也可能是孵化收集；要结合本关目标说明。解救对象要清除已确认覆盖，不能把每一个覆盖格都算作一个解救对象。

## 对玩家说什么

先报**动作所在区域**，再报棋子和移动方向，最后按需补一句任务依据。不说行列，也不只说颜色。

“右下方，魔力鸟向右与河马交换。右下冰面上也是河马。”

“右侧目标还在，但它周围的动物看不清，暂时不能确定交换。”

“灰毛球盖住了动物，先比较它上下左右的消除机会。”

实例中的事实必须在实际输入中存在，不能直接套用。
