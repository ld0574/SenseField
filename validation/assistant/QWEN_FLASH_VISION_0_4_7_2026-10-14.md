# 0.4.7 Qwen3.8-Flash：真实截图与思考模式对照

2026-10-14，实际调用用户提供的 `https://maas.qianwenaiapi.com/compatible-mode/v1`，模型为 `qwen3.8-flash`。关闭思考、开启 JSON 模式后，当前提示词下四次完整回答为 **1.79～2.14 秒**，均能通过协议解析；但仍有事实及建议依据问题。开启思考的八次回答为 **9.52～13.30 秒**，没有观察到足以抵偿延迟的稳定质量提升，暂不建议开启思考或将本轮记作策略验收通过。

## 方法与边界

使用已经保存的选人、战绩两张 960×432 开发诊断图及原问题，不要求用户重开游戏。它们是原失败请求附近的画面，不是此前手动上传的原图，也不是独立准确率留出集。图像来源和上传内容摘要沿用已固定的记录。

共 22 次请求，使用真实 `CompatibleVisionClient` 流传输与 `parse_visual_answer`。计时到完整正文返回，首个正文字符和思考流都不算可播报答案；每次上限 17 秒。思考实验只在私有脚本中将 `max_tokens` 调到 8192，避免中转把思考计入 256 token 时提前截断；产品配置和上限未扩大。另做两次同为 8192 token、关闭思考的控制调用。所有思考请求均观察到非空 `reasoning_content`，结束原因为 `stop`，只保留长度指标，不保存思考正文。

“协议通过”仅指字段及内容可以解析，不等于事实正确、建议有依据或策略最优。模型声明 `uncertain=false` 也不构成人工验收标签。直接调用不含生产网关、手机编码和语音播放耗时，样本量不足以计算正式成功率或 P95。

轻量思考和默认思考各两轮、每轮两张图，第二轮交换模式次序。`thinking_budget=512` 是发送的请求参数，不代表已通过供应商 token 统计证明严格执行了 512 上限。两次等额度控制调用表明本次慢并非仅由调高 `max_tokens` 引起；仍不能据小样本保证所有时段的性能。

用户控制台另报选人首包 734 毫秒、总耗时 2 秒，另一问题首包 719 毫秒、总耗时 1 秒。其上传原图、问题和完整请求参数未保存，独立记录为用户反馈，不并入上述直接调用统计。所报答案存在选人推荐未显示名称、另一问题转成出装的疑点；粘贴中的界面装饰文字未被当作协议故障或加入解析过滤规则。

## 采纳范围

保留 Qwen3.8-Flash 显式关闭思考时的顶层 `enable_thinking=false`，增加 `response_format={"type":"json_object"}`，中文协议提示明确要求 JSON。K3 等其他模型不新增该格式参数，通用游戏搭子身份和问题范围保留；不采纳重写提示词、两阶段推理或默认思考。相关 204 项 Python 回归已通过。

当前生产服务仍为 K3，本轮没有修改服务器私有配置、安装 APK 或更新公开版本。若试用这一候选，负责人需先更新 Python 源码，并在服务器私有配置中成套设置兼容接口、`qwen3.8-flash` 和 `ASSISTANT_GATEWAY_VISION_DISABLE_THINKING=1`；凭据只存服务器私有配置。速度已具备继续工程验证的价值，质量尚未具备“选人和策略已通过”的证据。

原图、问题全文、最终模型原文及凭据不进入公开仓库。[脱敏记录](QWEN_FLASH_VISION_0_4_7_2026-10-14.json)只保留源码与回执摘要、计时、协议结果及有限的事实核对。此前其他四款路由的 [22 次测量](REAL_GAME_VISION_LATENCY_0_4_7_2026-10-14.md)保持原绑定，与本轮 22 次请求分开统计。
