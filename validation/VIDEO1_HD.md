## 空间对齐

新文件不是旧画面的等比例放大。对 96.060 至 899.940 秒的 8 个配对帧，在把新画面降到 `720×324` 后使用 SIFT 特征、RANSAC 拟合旧画面到新画面的仿射变换。每帧有 39 至 119 个内点，8 次拟合的尺度范围为 `0.96386–0.96580`，720 px 坐标系中的横向平移范围为 `12.679–13.047 px`。

队列采用中位变换，将旧全屏归一化 `xywh` 映射为：

```text
x' = 0.964445*x + 0.01782728
y' = 0.964445*y - 0.00029722
w' = 0.964445*w
h' = 0.964445*h
```

坐标最终裁到完整画面。映射后的小地图方向参考范围为：

```text
widget_roi = [0.0526544476, 0, 0.1406481970, 0.3095749823]
```

在四周增加短边 3.5% 安全距离并裁到屏幕后的检测范围为：

```text
roi = [0.0369044476, 0, 0.1721481970, 0.3442777601]
```

对应原生画面约为 widget `[126.4,0,337.6,334.3]`、安全裁剪 `[88.6,0,413.2,371.8]`。ROI 用于模型裁剪，widget 用于判断图标是否属于小地图及计算方向，两者不能混用。

## 时间对齐

用旧人工复核帧在新视频对应时刻前后 ±2.05 秒内，以 50 ms 栅格对主游戏区域做灰度 NCC 搜索。排除准备／结束画面和一个不能唯一匹配的 281.333 秒样本后，19 个锚点覆盖 115.667 至 903.167 秒：

- Theil–Sen 斜率在 50 ms 栅格上为 0，即未测到全局漂移；
- 去趋势绝对残差 P50 为 50 ms、P95 为 100 ms、最大为 100 ms；
- 281.333 秒在不同局部区域出现互相冲突的峰，必须结合前后帧人工判断。

这些结果只支持“在 50 ms 分辨率上没有可测漂移”。队列保留旧时间戳，但所有迁移框仍需重新看高清帧，不能把时间对齐当作标签确认。

## 高清复核队列

私有目录 `data/private/minimap-review-video1-hd-v1` 包含 100 张完整 `2400×1080` 帧和 overlay，match id 为 `video1-hd`。它沿用低清密集队列的 100 个时间点，将 84 张旧正样本中的 133 个框按上述仿射变换写成可编辑建议；11 张旧负样本和 5 张旧排除帧没有建议框。

创建后的门禁结果：

- 100 张全部为 `pending`，0 张自动接受；
- 100 张帧与 overlay 都是 `2400×1080`；
- 133 个建议框均完整位于安全 ROI 内，框中心均位于 widget 内；
- 建议框只帮助定位，不能作为高清真值或训练标签。

标注时只框红圈敌方英雄头像。蓝圈队友、塔、兵线、野怪、信号和 widget 外 HUD 头像不框；对局中无敌人用 `negative`，准备、加载、结算或无法判读的全屏遮挡用 `excluded`。正样本必须保存为 `corrected`，逐图确认建议框、漏框和边界。

统一标注网站的启动命令见[团队协作文档](../docs/团队协作与本地运行.md)。网页选择 `video1-hd` 即可协作，所有队列共用 `8765` 端口。

## 分辨率结论

映射后，小地图有效采样由旧图约 `104×108` 提升为新原生约 `334×346`，边长约 3.21 倍、像素面积约 10.3 倍。肉眼可见的新原生帧保留了更完整的头像环和地图线条。

将新 crop 再 BOX 降回 `104×108` 后，20 个旧人工复核帧的 Laplacian 方差新旧比中位数为 0.706，P25–P75 为 0.641–0.757；mean absolute Laplacian 比例中位约 0.875，梯度 RMS 比例约 0.963。这个代理量同时受到降采样、旧图锯齿和编码噪声影响，不能单独解释为新图更糊。旧源 MP4 已缺失，因此不能诚实给出旧新码率、QP 或编码质量对照。可靠结论是原生小地图的有效采样面积约增加 10.3 倍。
