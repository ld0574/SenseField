# Android 14 首轮真人操作冒烟记录（2026-09-29）

本记录是首次实体手机、真实游戏操作链路诊断，不是验收通过证明。测试场景为 5v5 人机对局；未保存或公开游戏画面。原始日志位于 Git 忽略的 `validation/private/`，本页只保留非画面的汇总数据。

## 环境与边界

- 设备：Android 14，原生横屏分辨率 `2712×1220`
- 应用：`com.openkhub.sensefield` 0.2.1 debug
- 会话 ID：`8b1e9e47-e8f3-46a2-a902-ed5b34a2a76e`
- 模型：YOLOX Nano 320，HD bootstrap v2，固定小地图 ROI
- 测试 profile：`hok_minimap_hd_bootstrap_dev`，confidence `0.49`
- 日志观测窗口：10 分 18.604 秒；小地图事件窗口约 3 分 54.640 秒
- 日志缺少 `SessionSummary`，因此本轮不能确认最终帧数、平均 FPS、最大处理帧间隔或停止原因，也不能进入正式验收门禁

## 用户反馈与原因

测试者的直接反馈是：

1. 播放太频繁；
2. 出现“上方有敌人”但实际没有的错误提示；
3. 当前提示帮助有限。

日志确认，本轮没有走设计中的 `VISION_APPEAR`／`VISION_DISAPPEAR` 轨迹事件，而是走了旧的 `MINIMAP_ENEMY` 直通路径。`vision_memory=false` 时，`CaptureService` 仍会分发 kind 2；原生 profile 的 `minimap_min_gap_ms=5000` 又允许同类目标约每 5 秒重新提示。44 条事件中 37 个相邻间隔不超过 5.5 秒，这解释了持续打扰。

“上方”枚举没有上下反转，但它只表示检测框相对小地图控件中心的位置，不是敌人相对玩家英雄的方向。该语音来自未经轨迹状态确认的开发模型结果，确定语气不可靠。当前系统也没有识别玩家自身小地图位置，因此不能把这些方位解释成危险接近或战术建议。

## 已完成修复

- kind 2 原始检测不再直接生成用户提示；关闭视野记忆时保持静默，开启后也只允许带稳定 track ID 的状态变化路径生成提示。
- 短暂 `ImageReader` 断流恢复只写日志和刷新通知，不再播放“截屏已恢复”。
- 增加纯 Java 路由单元测试，锁定 kind 2 不得绕过轨迹层。
- 将测试 profile 的 confidence 从 `0.49` 提高到 `0.67`，并把原生直通保护间隔从 5 秒提高到 15 秒。

阈值调整后的固定开发诊断：

本轮查看了 video13 的多档阈值，因此 video13 从现在起属于开发数据，不能再称为独立 test 或用于最终门禁。video9、video12 仍保持封存。

## 下一轮通过条件

1. `vision_memory=false` 连续运行 30 秒，不得出现 kind 2 提示。
2. `vision_memory=true` 时，同一稳定目标只允许一次 `VISION_APPEAR`；静态保持 30 秒不得周期性重播。
3. 标准模式不播放“上方／下方有敌人”语音；任何详细方向提示都必须明确是“小地图方位”。
4. 自动恢复的短暂断流不得播放恢复语音；持续故障仍需明确告知并停止采集。
5. 从通知栏正常停止并记录唯一 `SessionSummary`，再统计帧率、最大帧间隔和完整会话结果。

即使下一轮达到这些条件，也只能证明提示策略修复有效。要判断功能是否真正有用，还需要识别玩家自身在小地图的位置，计算敌人相对玩家的方向和距离，并由目标玩家复测哪些事件值得提示。
