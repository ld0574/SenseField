## 调度修复与回归

`CueDispatcher.enqueueSpeech` 原逻辑允许普通近敌从 95→97→98 连续抢占。实局 burst 的三个事件方位分别为上方、右上和附近，不能称为相同方位重复。

用该段的相对观测／提交时刻与优先级构造 JVM 调度回放，完成回调使用受控时间，不冒充实际声音。修复前新增的三项行为检查失败；修复后覆盖：

- 缓存音频与普通 TTS 两条路径，评分上升时当前短句不被截断，新的音效与允许的振动仍立即送出。
- 等待中的旧语音被最新方位替换，语句、左右声像与该事件保持一致。
- 原 1.2 秒时效、用户关闭语音后不再播放、100 级预警抢占以及取消后的迟到回调。
- 原有不同 episode、助手让路和恢复、暂停／清空／关闭生命周期回归。

没有改变识别阈值、目标轨迹、预测窗口、两字开关、TTS 语速、方位映射或助手截图有效期。无法根据软件回调保证每条语音在真实扬声器上完整可听。

## 成本口径更正

最新片段 297.959 秒计数差：native 630 次、worker CPU 81,439 ms、诊断墙钟 187,770 **微秒**。诊断约占同段墙钟 0.063%，不能写成 63%；worker CPU 约占一个核 27.33%。这些是原手机会话的采样计数，不是本轮 APK 的完整前台成本或温升测量。

本轮移除采录实验，近敌调度只增加常数条件；合并的识别诊断复用原已计算的 admission，不添加模型推理或图像扫描。没有据此宣称量化性能达标；历史[成本失败](../honor/HERO_FEEDBACK_2026-10-14.md)及[当前验证范围](../STATUS.md)继续有效。

1. 采录脚本、页面、服务、编码器、构建变体与产品挂钩清理，正常提问保留。

3. 全量维护中的 Python、Debug／Release JVM、lint、native 和可用模拟器专项完成，实际测试范围及失败保留。
4. 最终 APK 身份、证书、资源、语音、对齐、Manifest 与 DEX 核验；保留旧摘要与回执，独立 APK 仅保留最终交付。
5. main 推送，v0.4.7 标签和 GitHub 普通 Release／Latest 对齐，附件上传后下载回验；本地 latest.json 与同包字节一致。
