# 0.3.5 事件前后画面与负载控制

日期：2026-10-02。版本 `0.3.5` / Android `versionCode 13`。用户要求兼顾问题定位和发热，先做一版复测。0.3.4 的 10 秒背景截图及触发当帧补拍不足以还原瞬时视觉变化，本版补上有界的前后采样窗口；并未据单次反馈更换模型、调整近区半径或宣称修复 03:07 的误报。

## 已实现的取舍

| 环节 | 0.3.5 策略 |
| --- | --- |
| 常规缓存 | 复用已经处理的 MediaProjection 画面，最多约每 500 ms 复制一组；主画面最长边 480 px，小地图最长边 512 px。没有第二条采集流，也不增加模型推理 |
| 前窗 | 在内存中保留最近 3 秒，最多 7 组；每组像素数组不超过 2 MiB，替换旧缓存时释放引用 |
| 触发当帧 | 保留原有清晰采样：主画面最长边 960 px，小地图最长边 768 px，优先进入图片队列 |
| 后窗 | 提示后继续保留约 2 秒采样；重叠提醒合并，延长截止最多为首次触发后 5 秒 |
| 自动片段频率 | 新自动片段起点至少相隔 10 秒；限流只限制额外前后片段，触发当帧仍尝试保存，真实保存结果另记 |
| 人工标记 | 采集通知新增「标记问题」。立即尝试保存近期缓存，下一处理帧补清晰画面和后窗；人工标记可绕过自动片段间隔。预缓存导出为下一清晰帧保留一个任务位和 6 MiB 额度 |
| 编码与写盘 | 仅背景采样、触发或活跃后窗进入共享后台 IO；缓存时不逐帧 JPEG 编码或写盘 |
| 队列预算 | 跨会话共享，最多 8 组排队／正在编码的像素数据，合计不超过 16 MiB；超限明确记录 `queue_limited`，不阻塞等待 |
| 保留上限 | 沿用每局图像 60 MiB、采样最长 20 分钟、最近 3 局 |
| 退出与停用 | 暂停、旋转及结束清除缓存，记录后窗是否中断。关闭画面保存清缓存并更新代次，待处理旧图片取消；已完成的旧文件保留 |

缓存 14 MiB 与图片任务 16 MiB 是原始像素数组的逻辑上限，二者可能共享同一对象；这些不是应用总堆内存上限。编码临时 Bitmap、JPEG、模型及 Android 内存另计。缩略图复制在采集处理线程执行，确实有计算开销；本版维持 0.3.4 的处理间歇和热档策略，是否保持体感改善必须同机测试，不能由缓存上限推导功耗或温度。

所有图像仍受「保存游戏画面」开关控制，只保存在手机本地，不自动上传。通知标记会改变操控或画面状态，请在问题刚发生后使用；记录的是服务处理标记请求的时间，不能作为精确手指触控时间。过晚标记、未自动触发、采样之间的瞬间、IO 超限或系统停止，仍可能缺少充分画面。本机制是采样上下文，不是连续录像或完整真值。

## 诊断关联与新增字段

- `image_context` 记录窗口 ID、接受／合并／限流、触发源、采样起止和前窗帧号。
- `image_request` 记录队列接受、已有请求、排队超限、为手动清晰帧暂缓的前窗等状态。前窗与当帧去重，不重复保存同一帧文件。
- `image` 保留真实保存的文件名、帧号、采集时间、输出尺寸、源 ROI，增加窗口 ID 和用途；`image_request_result` 区分完整一对、部分、未保存与取消。
- 检查点和摘要的 `image_context_stats` 记录缓存复制次数、累计／最大复制耗时、单组大小、窗口与限流／暂缓次数；共享任务计数与峰值明确标注为进程范围，不能混作当前一局独享内存。
- 每个处理帧的 raw observations、entities、relation 和真实采集时间继续保存。小图与这些数值需共同复核，不能用模型候选倒推视觉真值。

## 同机复测

1. 使用本次 0.3.5 安装包覆盖升级，在「测试记录与反馈」确认启用保存画面。保持与 0.3.4 相近的起始温度、亮度、画质、声音和充电条件。
2. 双手正常操控至少一段完整会话，重点看发热是否反弹、提醒是否变慢／漏掉。有误报或漏报时及时从通知点击「标记问题」，同时记下游戏 HUD 时间与提示方向；不用在操控中持续记表格。
3. 结束后停止辅助，导出这一局 ZIP。开发者先核对图片实际前后覆盖、限流／丢弃、复制开销、处理间隔与温度，再复核头像身份、位置和近区范围。若诊断负担明显增加，优先缩小画面／片段频次，不凭单例收紧模型或距离阈值。
