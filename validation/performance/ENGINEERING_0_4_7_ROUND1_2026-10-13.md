# 0.4.7 第一轮工程：提示生命周期、视觉反例与成本评估

日期：2026-10-13。对应[0.4.7 规划](../../docs/plans/0.4.7版本规划.md)的阶段 1～3；公开版仍为 0.4.6／code23。本轮复用既有资料并在模拟器验证，没有操作玩家手机，也没有发布新版本。

已修复同步播报完成被误报拒绝、重复／迟到回调、关闭语音后迟到开始，以及消消乐点读命令被捕获队列延迟的问题。真实开发画面的 11 格横向特效小黄鸡从身份已知但权限未知，改善为当前特效、覆盖和交换权限均有依据。两个负载方案未达到 CPU 收益门槛，均已回退。

局部视觉增量的三组同进程 P95 成本检查通过；整包重装对照的墙钟 P95 中位增幅 **+13.07%，超过 10% 上限，保留失败**。最终包成本、手机前台温升、实际发声与独立准确率仍未完成；本轮结果不构成 0.4.7 发布候选验收通过。

## W1／W2：提示归因与修复

`DiagnosticRecorder` 为请求增加类型、优先级、请求／获准渠道及创建／到期时钟。王者改用结构化 `CueDispatch`／`CuePlayback`，按请求会话检查记录器，并增加 `CuePolicy` 的分发时设置快照。原 `NearZonePresentation` 保留请求生成时的措辞及密集状态；两份证据不互相补填。

两款离线报告兼容旧日志，精确关联 cue／事件和请求时钟，允许同步回调先于分发事件落盘。请求前回调、错误身份／事件键、无准入渠道、到期后开始、重复回调和截断记录各自保留。缺回调表示缺证据；`STARTED`／`COMPLETED` 仅表示软件回调。

| 已复现问题 | 修复与验证 |
| --- | --- |
| 播放器同步完成后，已不在队列／活动位，提交却返回拒绝 | 保存该次提交的准入结果，保留一次完成终态 |
| 重复开始／终态或旧请求迟到回调污染当前状态 | 每次播放只接受一次开始及一次终态，并校验活动请求、会话 epoch 和取消状态 |
| 排队语音在开关关闭后迟到开始 | 开始回调重新检查类别及渠道，停止并记录 `SETTINGS_DISABLED` |
| 清类别、清全部、暂停、关闭时，排队和活动请求缺取消终态 | 记录相应 `CANCELLED_*`，旧回调不再追加完成 |
| 同步失败回调随后返回 false，又重复记录 UNAVAILABLE | 保留首次失败终态，避免覆盖同步回调已启动的下一请求 |
| 音效重复回调 | 原子状态去重，继续避免 SoundPool 回调取得 dispatcher 锁所造成的锁顺序风险 |
| 点读 ON／OFF 被已排队捕获延迟，前插命令又可能倒序 | 由 worker 执行前插命令，主线程只发布最新命令版本；只执行最新版本 |

新增 CueDispatcher 反例先在基线 **34 项中失败 4 项**，修复后扩展的 **36 项全部通过**。点读可控队列反例修复前失败，修复后及相关断言 **5／5 通过**，完整 Debug 也覆盖了该用例。先前另一个两秒生命周期等待用例在隔离运行中已通过；没有据此宣称建立了它的唯一根因。

现有 6 秒消消乐播报间隔、3 次尝试上限及王者措辞开关继续沿用。本轮没有重设策略阈值。

### 王者感知

没有改动训练模型、阈值、ROI、跟踪或定位策略。完整旧观测流按原时间戳进入 native：250／500ms 两个年龄预算各接受 5,531／5,533 个观测，均有 25 次 NEAR_ENTER、8 次 RADAR_PAUSED、7 次 RADAR_RESUMED、19 次 NEAR_SUPPRESSED，并分别执行 3 次黑帧、3 次尺寸变化重置。

新增模拟器实际检测器入口冻结 512 模型、当前 profile、ROI、阈值及 500ms 预算。12 张输入由抽样屏幕 JPEG 放大并恢复原尺寸地图裁图，包含非游戏画面；它们不等于原采集像素，也不是连续轨迹或独立真值。该 profile 的定位器开关为 **false**，不能记为已验证自动小地图定位。Debug 墙钟／worker CPU P95 为 121.716／44.187ms，最终 Release 为 114.378／35.830ms，forward 约占 Debug 所记录 native 阶段总墙钟 95%。两种构建并非交替配对，不能把这个差值当作优化收益。

Debug 与最终混淆 Release 的 12 张 raw 检测、ROI、定位状态、实体数和关系状态／事件逐项相同。JNI 将实际推理时间计入引擎帧龄，分别保留实际值，不重写为相同事件时钟；这批帧龄 Debug 106～117ms、Release 106～110ms。

## W3：两个方案回退，视觉成本分项报告

使用同一模拟器、26 张冻结输入和固定工作量。每张图运行生产采样、逐格确认、HUD 和排序；HUD 每张图清缓存，6 轮预热、15 轮测量、每图 3 次采样。分别保存墙钟、worker CPU 和全进程 CPU，排除采集、实际播放、日志 I/O 及游戏本身。不能把这份固定工作量当作实局功耗。

| 纯成本方案 | 三组全进程 CPU 变化 | 中位变化 | 决策 |
| --- | --- | ---: | --- |
| HUD 目标模板批量评分／精确缓存 | −9.60%、−1.73%、−8.99% | −8.99% | 未达至少 10% 降幅，回退 |
| 预计算采样偏移／未变像素工作区 | −51.33%、−1.69%、+4.67% | −1.69% | 收益不稳定且未达门槛，回退 |

两者生产改动均撤销，原始失败数据保留，没有启用未达标缓存或采样路径，也没有依据异常首组的大降幅宣称降温。王者本轮定位 forward 占比，继续冻结已有推理路径，没有追加第三个优化方案。
