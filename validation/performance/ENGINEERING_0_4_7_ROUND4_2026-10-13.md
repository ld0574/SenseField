# 0.4.7 第四轮：当前帧几何计算的生产优化

2026-10-13。以 `main 0b8e4db` 为基线，保留当前帧像素的批量读取与原生几何算术。最终压缩 Release 的三组动态处理配对已达到原门槛：**全进程 CPU 配对降幅中位数 10.83%，每组墙钟与 worker P95 增幅均不超过 10%**；逐格状态、权限、目标、门控、排序和新提示坐标相同。616 项 JVM、最终 116 项 Debug／82 项压缩 Release 及两种构建的生产回放通过，失败／跳过均为 0。

## 实际改动

`Match3Sampler` 将棋盘背景占用扫描、亮度／边缘剖面改成有界像素带读取，由 `Match3NativeMath` 执行原生算术。像素仍取自本次 `Bitmap.getPixels` 的规范 ARGB 数据，不直接读取含预乘 alpha 的位图存储。背景色范围、单像素边界、采样步长、逐项浮点累加顺序与自相关算法保持原定义；缺少原生库时使用原 Java 路径。

每个调用线程最多保留 65,536 个 int（256 KiB）工作区。读取前覆盖当前带，跨帧不保存识别结果；异常大尺寸只使用临时数组。背景掩码和后续碎片、方格相位、权限判断仍依赖当前帧。

新增 5 项数值与占用检查：跨带／横纵轴／步长／alpha 的 double 位相等、修改原 Bitmap 与并发调用、无效数组范围、全部 16,777,216 个 RGB 颜色及粗网格内每个细边缘位置。新增剖面观察入口只保留一个测试所需的 R8 方法签名。
